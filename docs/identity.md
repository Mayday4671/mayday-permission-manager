# 企业登录与多因素认证

本地账号仍是权限主体。企业 OIDC 只证明显式绑定的外部身份，不能按邮箱、组织组或外部角色自动建号和授权。部署未配置提供方时保留原密码登录；提供方故障时已有本地登录通道继续可用。实现和接口专项已有验证，最终验收状态见 [完整功能追加记录](full-functions-validation-20261004/README.md)。

## 部署配置

开启个人 TOTP 时设置 `MAYDAY_MFA_ENABLED=true`，并在 `MAYDAY_IDENTITY_ENCRYPTION_KEY` 提供独立生成的 32 字节随机密钥的 Base64 编码。`MAYDAY_IDENTITY_LABEL` 是认证器内站点名称。密钥不进入系统参数、公开接口或仓库；数据库恢复必须同时恢复该密钥，否则原认证器秘密不可解密。关闭开通开关不会绕过已开通账号的验证。

OIDC 提供方使用 `.env.example` 中 `MAYDAY_IDENTITY_PROVIDERS_0_*` 配置。先在身份提供方注册机密客户端与固定回调 `/auth/oidc/callback`，再填写 issuer、client ID/secret、授权、token、JWKS 和回调地址，最后启用。客户端认证支持 `client_secret_basic` 和 `client_secret_post`。生产地址全部要求 HTTPS，无凭据、无片段；issuer 不能带查询，回调不能任意跳转。开发 HTTP 仅接受字面 loopback。多个提供方用 Spring indexed 配置，最多 10 个，并给每个提供方唯一标识；Compose 模板显式传入第一个，增加其他提供方需同时补部署注入。

仅启用 OIDC 而不开通 MFA 时也必须设置同一加密密钥，授权挑战的 state、nonce 与 PKCE 使用该密钥保护。任何已启用提供方缺少合法密钥会拒绝启动。

不要从登录请求或 JWT 的 `jku/x5u` 动态选择网络地址。服务器只访问部署注册的固定端点，禁止重定向，有响应大小和超时限制。授权码交换采用 state、nonce、PKCE，并检查签名、issuer、audience、有效期及浏览器/来源关联；一次性挑战存数据库。公开页面只得到提供方标识和名称，不能读取客户端密钥、身份映射或访问令牌。

## 绑定与本地账号

用户先用本地账号登录，在个人中心输入当前密码，已有 MFA 时再验证当前因素，然后主动绑定企业身份。回调要求原会话仍有效，绑定当前用户；未绑定企业身份不能通过邮箱碰巧匹配到管理员。解绑也需本人近期再认证，精确删除本人绑定并撤销会话。提供方停用后仍可通过本地登录解除旧绑定。

企业身份登录后仍检查本地启用状态、角色与会话规则。已启用 MFA 的账号必须完成第二因素才能获得业务令牌，企业登录不替代 MFA；解绑、改密或因素代际改变后旧挑战不能继续签发会话。

## 开通、恢复与敏感操作

个人中心的开通流程先验证密码，展示一次待确认密钥及认证器二维码，再提交真实验证码完成开通。仅扫码不算开通。密钥使用 AES-GCM 加密入库，不能从状态接口反查。开通后撤销旧会话，返回 10 个一次性恢复码；请保存在安全位置，页面关闭后无法反查明文。

同一个 TOTP 时间计数不重复接受；并发消费恢复码只有一次成功。挑战最多 5 次错误，账号及来源失败窗口跨挑战、跨实例保留；另开验证页面不清空失败次数。恢复码只替代第二因素，不能绕过密码或企业身份的首因素。

重新生成恢复码、关闭 MFA、解除企业绑定和修改密码均要求相应近期再认证并撤销旧会话。轮换恢复码、关闭或管理员恢复 MFA 后，旧恢复码失效；解绑和修改密码保留现有 MFA 恢复码，但旧绑定或旧密码代际的登录挑战不能继续签发会话。认证器与全部恢复码都遗失时，有用户重置权限的管理员可在可管理范围内填写理由，经自己当场密码及已启用 MFA 验证后恢复目标账号。不会修改目标角色或企业绑定，也不会给目标发一个绕过验证的永久凭证；目标需重新开通。关键变更记录脱敏审计，不保存验证码、密钥、恢复码或原始令牌。

## 多实例与二次开发

所有实例使用同一身份数据库、相同提供方配置及加密密钥；一次性挑战、TOTP计数、恢复码和失败窗口在数据库内原子处理。业务令牌仍使用原会话服务，不能将企业 access token 当本地 Bearer 使用。前端回调只接固定路径，不暴露后台入口给公开门户。

增加新业务权限仍需按 [权限模型](permissions.md) 接入。OIDC/MFA 不代表多租户隔离、SAML、完整身份平台或外部权限同步已实现；这些能力有不同的业务边界，不能通过放宽绑定校验来补齐。
