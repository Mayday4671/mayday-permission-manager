# UDP 转发验收 · 2026-09-22

已交付独立模块与后台操作入口，Windows 原生和容器同一 JVM 后续运行满足本轮 250 Mbps、30 秒无缺包检查。**Docker Desktop 冷启动零丢包和真实网卡验收仍未通过/未执行**，不标记为任意环境“绝不丢包”。

## 交付内容

- `mayday-netty`：独立 Maven 普通 JAR，JDK 17+，不依赖 Spring/MySQL/Mayday；Netty 传输依赖全部为 4.1.105.Final。
- 单播 UDP 单路接收、单目标转发，页面配置接收/目标 IP 与端口，配置持久化。按从 1 开始的字节位置，只将第 3、4 字节改为 `03 01`，其余负载完整保留；不足 8 字节单独计数丢弃。
- 复用后台菜单、标签页、弹窗、授权与主题；每秒接收/转发统计，60 个速率样本，实际缓冲、待发送、内核/应用丢包分项。没有逐包数据库写入或日志。
- `relay:view/configure/control` 分别控制查看、修改、启停；普通角色不自动获得新权限。运行中不能改配置，保存检查版本，停止检查批次；应用重启不自动开始监听。
- V16 与唯一 `database/mayday.sql` 同步，40 表、370 字段均有中文 COMMENT。

## 实测数据与限制

[原始结果](results.json) 保留最终代码冷启动失败和后续运行成功的全部逐秒快照，以及 Windows 原生结果，不删除失败记录。

1. **Windows 原生 / NIO / 新 JVM**：本机 19010 → 19011，30 秒、1472 字节、636,888 包，发送 250.000 Mbps、接收 249.993 Mbps。缺失、重复、内容错误、乱序均为 0。每包第 9–16 字节为测试序号；逐包校验其余所有字节，包括固定替换的 `03 01`。
2. **Docker Desktop / Linux EPOLL / JVM 重启后的首轮**：申请接收缓冲 16 MiB，实际只有 425,984 字节。30 秒发送 636,888 包，应用和对端均收到 636,668 包，内核丢包 **220**。应用内丢弃、发送失败、内容错误为 0；这轮验收失败，页面正确报告内核丢包。
3. **相同部署 / 同一 JVM 再次启停**：30 秒发送、接收、转发、唯一接收均为 **636,888**，累计转发 **937,499,136 字节**，接收 **249.999 Mbps**。所有丢包、失败、待发送、重复、错误、乱序为 0；逐秒速率有至少 20 个样本持续超过 200 Mbps。

源端与接收端临时容器共享后台网络命名空间，只使用回环地址，没有向第三方、局域网设备发流。原始报文体未持久保存。未修改宿主全局 sysctl，也未增加容器特权；首次分配优化只能减少启动开销，不能代替系统缓冲配置。

真实网卡、交换机、跨主机链路、不同包长/PPS 和长时间运行需要在目标服务器重新验收。当前结果不代表 200 MB/s，也不代表小包高 PPS 或任意网络都能不丢包。

## 复测

在独立模块目录先执行 `mvn test dependency:copy-dependencies -DincludeScope=runtime`，然后使用模块 README 中的 Java 命令。Windows 如 Docker 已占用 19000，请添加 `--input 19010 --output 19011`。

已部署后台的回环复测为 `node scripts/verify-udp-relay.mjs`。脚本只在转发停止且仍为默认回环目标 19001 时运行，不擅自改配置或停止别人的批次；临时接收器启动后发流，保存完整结果，最后只停止自己创建的批次。该命令失败时应保留证据并定位，不通过反复运行删除或替换失败记录。

实际部署的缓冲检查、Docker 端口映射、权限和迁移说明见 [UDP 转发指南](../udp-relay.md)。
