## 1. 交付目标与范围

交付一个可安装、可升级、具有真实数据和权限校验的模块化后台，技术继续使用 React、Ant Design、TypeScript、Java、Spring Boot、MySQL。

这轮覆盖系统管理、通知中心、审批中心、内容管理以及它们驱动的前台门户。参考站的 21 个主页面作为功能覆盖依据；用户统计按真实账号和登录数据实现，不采用共享账号访客估算。

固定界面约束：

- 保持现有单侧菜单，不增加左侧模块栏或两级侧栏。可以用当前的分组标题组织入口。
- 保留标签页、关闭其他/右侧/全部、刷新及权限变化后的页签清理。
- 新增、编辑、处理和详情使用弹窗；复杂内容编辑可以用宽弹窗。流程设计器使用独立标签页，节点配置使用弹窗，不使用抽屉。
- 去掉装饰性大标题、口号、说明横幅和无实际业务意义的卡片。必要的字段帮助和操作反馈保留。
- 页面名称只放在导航、面包屑和标签页；正文直接进入查询、操作或数据，不增加“数据概览”等泛化标题，也不为日期、重复刷新按钮单独保留一行。必要的分区名称、字段标签、表单操作提示不属于装饰文案。该规则适用于所有后台页面与以后新增页面。
- 首页没有内容溢出时不出现页面滚动条；确实超出屏幕的内容正常滚动，不以裁切或隐藏数据解决。
- 前后台都提供详细注释，重点解释组件契约、权限边界、状态变化、事务、版本检查及异常处理。

暂不开发 CRM、电商、人事、招聘、数据大屏、多租户、代码生成器、复杂 BPMN、外部邮件/短信服务。已有监控、独立任务管理等半成品保留，暂不作为这轮交付范围。定时发布、消息重试所需的后台执行机制属于本轮范围，不要求同时交付通用任务调度管理台。

## 3. 执行顺序与里程碑

按 P0 → P1 → P2 → P3 → P4 → P5A → P5B → P6 执行。P5A、P5B 属于同一审批阶段的两个验收批次。

每批次都交付页面、接口、数据库变更、权限、必要测试和说明。某批次的验收未通过，不以“页面已经画好”标为完成。

### P0：恢复可验证的开发基线

状态：已完成。前端构建、后端构建与 3 项单元测试、7 项标签页测试、两种安装路径各 25 个接口场景通过；备份恢复、授权保持和重启检查通过。[验收记录](baseline.md)

任务：

- 盘点已接入与未接入的源码，确认运行版本、数据库迁移版本与工作目录的差异。
- 检查 V3 迁移是否已应用；已应用的迁移只追加修正，不能直接改写已执行记录。
- 运行前后端构建、现有接口和页签回归，修复半成品带来的编译、兼容及测试清理问题。
- 固定角色/权限名称、接口分页与错误结构、版本冲突响应，以及新模块路由登记方式。
- 建立不覆盖现有业务数据的开发验证数据；记录升级前备份和恢复方法。

验收：现有用户、角色、内容、登录和页签行为通过回归；新代码没有破坏原有数据；后续功能可以在同一基线上验证。

### P1：公共组件、后台框架与权限扩展

状态：核心组件、用户与字典示范页及权限扩展已通过接口/浏览器验收，[证据](p1-validation/README.md)。富文本与附件公共组件已通过 P3 通知和 P4 内容两个业务的保存、读取与权限验收。

任务：

- 路由、菜单和页签使用同一页面登记来源，避免有菜单无页面、页面可访问但页签无法恢复等分裂状态。
- 扩展通用查询栏、表格列配置/密度、权限动作、异步选择器、批量操作和导出反馈。
- 完善表单/详情弹窗：标题与按钮规范、提交锁、错误定位、未保存修改提醒、内部滚动、键盘焦点、可访问名称。
- 提供人员、部门、角色、字典、分类、标签选择器，以及富文本和附件上传组件；业务页面组合使用，不重复编写。
- 在现有四种数据范围上加入自定义部门集合，明确多角色合并规则和授权委托限制。
- 将权限落到菜单、操作、接口、数据范围、字段读写；列表、详情、统计、导出使用一致范围。
- 校正首页高度、表格固定列、窄屏布局；保留当前单侧菜单与标签页方式。

验收：选择用户管理和字典管理作为示范页面；切换角色后菜单、按钮与接口结果一致；越权 ID、导出、字段修改、自定义部门及多角色组合有针对性回归；页面与弹窗在常见桌面尺寸和窄窗口下可用。

### P2：系统管理补齐

状态：已完成。11 个系统页面、类型参数/缓存、网站配置白名单、分离日志、真实用户统计、菜单登记与引用保护通过接口和浏览器验收。[证据](p2-validation/README.md)。网站配置的门户最终呈现在 P4 验收。

任务：

- 用户：角色/部门/岗位关联、筛选分页、启停、导出、密码重置等操作形成一致权限规则。
- 角色：操作权限矩阵、各资源数据范围、字段权限和授权边界；保护内置管理员及已引用角色。
- 部门/岗位：层级、负责人、排序、启停与引用保护；部门树拒绝循环。
- 字典：拆清字典类型与字典项，支持值唯一、标签样式、排序、启停和业务选择器联动。
- 参数：按分组和类型管理，校验值，保护内置键；缓存刷新有明确效果，业务读取使用同一配置服务。
- 菜单：名称、图标、路径、顺序、可见和权限关联；只允许已实现且登记的页面，不允许配置任意地址成为内部授权入口。
- 日志：操作与登录分开查看，支持实际需要的筛选、详情及授权导出；日志内容统一脱敏，清理保留独立权限。
- 用户统计：真实账号数量、启停数量、登录成功/失败、按明确时间窗口统计的活跃账号；各指标注明口径。
- 网站配置：品牌、介绍、SEO、联系/版权/备案配置及预览；只通过白名单暴露公共字段。此阶段提供配置能力，P4 验证前台呈现。

验收：11 个系统页面具备完整入口和真实数据；改字典/参数能在对应业务生效；授权变化及时生效；不以虚构数据填充统计卡片。

### P3：通知发布与个人收件箱

状态：已完成。通知管理、收件箱、富文本及附件闭环通过接口和浏览器验收，[证据](p3-validation/README.md)。审批/内容关联通知、事务事件重试与防重已随 [P5](p5-validation/README.md) 完成。

任务：

- 区分通知正文/发布记录和每位接收者的投递/阅读记录，管理列表不会为每个接收人重复展示同一通知。
- 支持通知类型、标题、摘要、正文、附件、草稿、发布、撤回、过期及复制。
- 接收范围支持全部、部门、角色、指定用户；发布时检查可发送范围并保存接收人快照，避免后续组织变化悄悄改变已发通知。

状态：已完成。不可变修订、发布记录、分类标签、文件边界、回收站、排期、权限撤回及门户经过接口/浏览器验收，[证据](p4-validation/README.md)。修订绑定审核及批准后独立发布已随 P5 验收通过。

- 编辑支持封面、标题、摘要、正文、公开范围、分类、标签、排序、置顶、推荐、SEO；富文本在服务端处理不安全内容。
- 草稿、待审核、审核通过、待上线、已上线、已下线、已删除具有明确流转规则；已上线内容的新修订不直接覆盖正在展示的版本。
- 完成分类、标签、回收站；恢复回到草稿，彻底删除单独授权，引用文件按保留规则处理。
- 具备直接发布权限且业务未要求审批时，可以发布；需要审批的内容在 P5 接通前不放行。
- 支持定时上线/下线，时间使用统一时区约定，重复执行不产生重复发布。
- 前台列表、搜索、分类、标签、推荐区、文章详情读取真实后台数据；网站公共配置用于实际标题、页脚和联系展示。
- 公共接口、内容附件与封面访问共同检查可见性；下架/删除后不能通过详情直链或旧缓存继续访问受限内容。
- 浏览统计由后端按确定口径生成；点赞、评论等互动不在本轮无依据扩展，表单不提供随意修改统计数字的入口。

验收：创建草稿前台不可见；发布指定修订后前台一致展示；编辑新修订不改变已上线版本；定时发布、下架、软删除、恢复、搜索和直链访问符合规则。

阶段演示：管理员维护网站信息并发布一篇文章，访客在前台看到相应配置和内容。这是第一个完整的前后台交付节点。

- 实现顺序节点、指定人员/角色/部门负责人解析、或签/会签、发起范围与无有效审批人的处理规则。

## 4. 模块职责

保持模块化单体，继续使用当前 Spring Boot 与 MySQL，不在这轮引入微服务。

- `mayday-common`：响应、分页、异常、基础实体与通用契约。
- `mayday-security`：认证、授权、数据范围、字段策略、授权委托边界。
- `mayday-system`：用户、角色、部门、岗位、字典、参数、菜单及审计。
- `mayday-content`：内容修订、分类标签、发布记录、回收站和公开查询。
- `mayday-netty`：独立、可迁移的 Netty UDP 转发核心；Spring 配置/权限适配保留在 application，逐包路径不访问数据库。
- 通知、审批、文件分别形成明确业务边界，从 `mayday-operations` 中逐步整理；是否新增 Maven 子模块以避免循环依赖和独立测试为判断依据，不做仅改目录的拆分。
- `mayday-application`：启动、配置、迁移与跨模块用例编排。控制器保持轻量，核心规则进入可测试的服务。
- 内容与审批通过业务关联及明确契约衔接；双方不互相直接修改数据库。审批通过后的发布由应用服务校验内容修订和发布策略。
