# 工程底座扩展验收（2026-10-02）

按用户确认的前三项扩展交付：业务模块生成器、项目模块开关、CI 质量检查与接口契约。使用步骤见 [二次开发与工程规范](../engineering.md)。UDP 转发核心没有修改；应用层相关文件仅随统一格式整理。

## 已交付

1. **业务模块生成**：配置预览后生成独立 Java 模块、前端公共列表/弹窗、请求和响应 DTO、动作权限、菜单/路由、模块开关、新迁移、统一 SQL 及服务安全测试。拒绝危险标识符、路径穿越、符号链接、已有模块/实体冲突和失效登记标记，不连接数据库或覆盖已有业务文件。已生成可运行的工单示例，默认关闭。
2. **模块裁剪**：启动配置统一决定 API、附件、权限候选、会话授权、菜单、恢复页签、直接路由和后台任务。内容关闭会关闭门户；消息关闭会关闭审批。关闭模块后管理员也不能通过直链访问，原表、业务数据和已保存授权保留。
3. **工程规范和契约**：Java 自动格式化进入 Maven 检查阶段；前端、工具与测试使用 Prettier。OpenAPI 从真实控制器生成，提供固定操作标识、授权说明、明确的新业务 DTO 和生成的前端类型。公共类型请求客户端已用于登录、会话、模块状态和工单写入。GitHub Actions 执行前后端检查、真实数据库安装/升级、模块裁剪和契约比较。

新增模块的创建人、部门、时间由服务端确定。分页在 SQL 层过滤范围，直接 ID 的读写再次校验；DTO 不开放实体身份字段，编辑和删除均校验乐观锁。注册目录外的权限默认拒绝，即使存储中残留未知授权也不会生效。

## 使用边界

生成器当前提供字符串、整数、布尔字段的基础 CRUD，金额、关联关系、转派、复杂流程与多租户需要自己的业务规则和测试。旧模块的动态 Map 或 `ApiResponse<?>` 响应仍是通用结构；新增 DTO 及部分认证/用户接口已收紧，不能声称所有历史接口均已获得完整字段类型。

模块开关需要重启，保留表和数据，不能代替租户隔离。GitHub Actions 已提供自动检查，但合并必须通过检查的分支保护仍需仓库设置。后续业务改动需重新运行检查；本记录不承诺任意业务或部署环境直接上线无风险。
