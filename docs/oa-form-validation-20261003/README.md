# OA 表单设计验收（2026-10-03）

用户反馈旧表单编辑器只有控件按钮和大字段卡片，属性需反复开弹窗，不能作为正常 OA 表单设计工具使用。本批重做设计交互，保留 Java 运行契约、稳定字段引用和已发布申请快照；不更换流程引擎，不增加数据库迁移，不改唯一安装 SQL。

## 交互与参考

参考 [飞书官方表单设计说明](https://www.larksuite.com/hc/zh-CN/articles/360043705794-%E7%AE%A1%E7%90%86%E5%91%98%E8%AE%BE%E8%AE%A1%E5%AE%A1%E6%89%B9%E8%A1%A8%E5%8D%95)、[飞书审批控件说明](https://www.feishu.cn/content/article/7584390246654037188) 的控件库、表单编排和属性编辑方式。此处为官方资料研究，不宣称登录或验收了参考产品的全部业务。

- 左侧 13 类控件分组、搜索、点击添加；拖到字段前或末尾精确插入。
- 中间直接展示表单，选择字段后右侧即时修改属性；字段支持拖动、上下移动、键盘排序、复制和确认删除。
- 单选/多选逐项编辑、排序、增删；明细表逐列选中并设置，不使用长段文本配置。
- 保留原 ID、类型、选项原值及未编辑属性。复制深拷贝并生成新 ID，不自动继承节点授权；删除清理本地节点读写引用，条件正在引用时禁止删除。
- 撤销/重做与整页保存状态联动，连续属性输入合并记录；保存期间冻结编辑与重复操作，发布权限独立于编辑权限。
- 桌面/手机尺寸预览，实际控件试填与检查；日期区间和明细内部约束不能仅用顶层必填判断。同一明细的多个错误一起展示。
- 窄屏使用控件、属性弹窗，沿用主题和滚动条；设计态不查通讯录、不上传附件。填写预览可查询当前账号获准的人员/部门，附件上传仍禁用，不生成业务申请或文件。

## 校验与兼容

新草稿保存、发布和模拟都拒绝已经不存在的单选 `EQ/NE` 比较值，明确指出字段和条件节点，不自动改写条件。草稿仍允许审批人、起点和连线尚未配置完成，字段结构本身必须有效。

历史申请从数据库内的冻结快照运行，不能由客户端传入宽松校验标志。旧快照只保留旧单选比较语义；循环、字段授权、发起人归属、当前审批权限等仍校验，普通办理、退回修改重提不能被新设计规则意外改变。

旧 nullable 配置视为缺省，不因打开属性面板而改写。重复字段/明细列 ID 明确拒绝批量修改或删除，保留原数据供修复。前端校验只读取自有值键，`constructor`、`toString` 等合法字段标识不能误读对象原型。

## 浏览器实测

内置浏览器重连仍失败，用户明确授权独立测试浏览器及两次本机隔离登录滑块。使用独立 Edge 上下文，只访问本机 15174，正常 UI 登录；不复用其他浏览器账号、不注入令牌、不绕过验证。

组件样例使用实际组件和主题、合成报销模型，仅用于最先检查布局与原生拖放，不能替代整页业务验收。已检查 1440×1000、1280×720、2560×1389、390×844，无全页横向溢出；长表单只在编排区正常滚动。手机属性弹窗宽 374 像素、两侧各留 8 像素。证据见 `viewport-measurements.json` 与 01–05 截图。

随后正常登录隔离后台，从费用报销模板建立“表单体验验收 20261003”（定义 23），实际将“费用说明”改为“报销用途”，拖入“费用发生日期”并保存、发布版本 1。原生拖放、即时属性编辑与 Java 持久化一起通过，而非仅有合成组件截图。

真实申请填写差旅、120.50 金额、2026-10-01 至 2026-10-02 的日期区间、交通明细及用途后提交。指定隔离管理员办理，退回申请人并填写理由；原字段、日期、金额和明细正确回填，修改用途后从起点重新提交，第二轮同意结束。历史保留第 1 轮提交/退回、第 2 轮重提/同意，不复用旧待办结果；通知状态页显示 4 项已投递、重试 0 次，顶栏同时出现 4 条未读提醒。测试流程明确启用本人审批，仅用于隔离数据；不修改日常业务配置。证据见 08 截图。

冷启动刷新实测发现 React StrictMode 的旧身份请求提前结束加载，使入口返回目标丢失流程编号。修复后，旧请求不能放行守卫，刷新、直接访问和切回页签保留 `id=23`；登录返回目标与页签共用安全白名单，只允许现有路由及合法流程 `id`、审批详情 `record`，不保存 schema、试填值或凭证。权限撤回、退出、切账号、外链/非法参数及旧响应有独立回归。

整页手机实测还发现固定画布高度不能适应换行页头，改为按实际起点测量剩余窗口高度。最终 1440×1000、1280×720、2560×1389、390×844 的整页宽高均无溢出；长表单在画布内滚动，手机属性弹窗为 374×780、两侧各留 8 像素。尺寸详见 `real-viewport-measurements.json`；09–12 为真实隔离页面的桌面、手机和深色截图。极矮窗口保留 240 像素最小操作区域，允许必要滚动。

上述完整链路和外观验收已完成，浏览器无页面脚本错误。日常 15173/18080 的业务库不写入验收数据；独立数据库与日常数据库卷分开。本次不将多人审批、所有分支或并发场景宣称为浏览器全覆盖，相关服务端证据保持原记录。

最后补查系统“减少动态效果”设置，发现原全局 `animation: none` 会吞掉 Ant 的动画结束事件，使弹窗停在透明入场状态。改为极短动效时长并保留结束事件，正常及减少动效模式的审批详情、主题抽屉、手机字段属性均可打开与关闭；本次减少动效截图仍使用真实页面，不修改 DOM 强行显示。修正后补跑格式、源码规范、类型和生产构建，未改业务逻辑或删除检查。

手机属性弹窗关闭后回到桌面，原固定控件 ID 会与留在 DOM 中的弹窗副本重复，破坏标签关联。字段、明细列与明细行数改为每实例稳定且唯一的 React ID，避免标签聚焦到隐藏输入；补充多实例回归并实测手机→桌面往返，不重新编号业务字段。
