# Telegram 模块部署与验收

最新真实极搜采集、预览、下载与运行修复结果见 [2026-10-24 实际联调验收](telegram-acceptance-20261024.md)。下文带日期的历史记录只代表当时范围。

## 模块能力与边界

Telegram 是随 Mayday 主应用装配的独立 `mayday-telegram` Maven 模块，默认关闭。入口位于后台“Telegram”菜单；关闭时菜单隐藏、Telegram API 被模块守卫拒绝，原有系统不依赖 TDLight native。业务数据通过 MyBatis-Flex/MySQL 保存，采集文件使用平台 `FileStorage`，TDLib 加密会话保存在服务端配置的私有目录。

当前代码支持单个授权用户账号的连接状态与授权挑战、受控机器人搜索及原始消息查看、按钮快照、候选来源链接识别，以及已加入频道/可访问消息链接的有界历史采集。采集任务最多保存 500 条历史消息，可按包含式日期范围过滤；任务支持暂停、继续、取消、失败重试、服务端消息分页和媒体状态查看。完成且未设置结束日期的频道任务可由用户单独启用定期追赶：最多每 30 秒检查一次，使用独立于历史回填的游标/租约，最多检查 10,000 条后自动停止；此功能是有界轮询，不是 Telegram 推送，也不保证即时或完整送达，不会自动加入频道。采集策略可选择仅保存文本/附件元数据，或保存图片、视频、文档。取消任务会停止排队中的媒体下载；已开始的下载即使完成也不会在任务取消后发布为可访问文件，重连时也不会重新排队。媒体下载使用有界后台工作线程、数据库租约、三次尝试上限和平台文件存储。图片/文件读取要求实时校验 `telegram:view`、`telegram:download`、数据范围、原消息可保存状态和任务下载策略。原始 TDLib 文件 ID、磁盘路径和媒体存储键不会返回给浏览器。

## 已加入频道浏览

频道已独立为“Telegram → 频道”页签，与极搜、采集记录、账号与连接并列。左侧直接列出当前账号的频道，不需要先输入关键词。列表支持搜索、继续加载主列表及归档列表；右侧按时间浏览频道消息，使用“加载更早消息”向前翻页。手机端先展示频道列表，选择后进入消息页，可返回列表。

频道消息支持关键词、图片/视频/文件/音频/链接类型和日期组合查找。关键词与类型通过 TDLib 的频道搜索索引查询完整可访问历史，并非过滤当前页面；结束日期先定位历史锚点，开始日期作为停止边界。搜索结果保留原生继续游标，每次最多检查 100 个候选，空批次但有游标时可继续查找。

消息中的图片、视频和附件按钮复用现有鉴权预览；“采集这条消息”保存选中消息及同组相册，“按日期采集”可设置日期、条数和附件类型。勾选筛选结果后可批量创建采集任务；批量模式只保存勾选消息，不扩展整组相册，防止重复采集。逐条提交的失败项保留勾选并显示错误，可单独重试；成功项取消勾选。“查看采集记录”切换至独立的采集记录页签。单纯浏览不创建任务、不自动加入频道，也不标记已读。读取历史和解析消息链接前均重新校验频道成员身份；受保护消息不返回正文或提供下载入口。

新增接口为 `GET /api/telegram/channels`、`GET /api/telegram/channels/{chatId}/messages`、`GET /api/telegram/channels/{chatId}/messages/{messageId}/link`。目录和历史使用 `nextCursor` 继续读取；TDLib 可能先返回短页，不能把不足一页当作历史结束。`GET /api/telegram/channels/{chatId}/search` 接受关键词 `query`、媒体 `type`、分页 `cursor` 和 Unix 秒日期边界 `from`/`to`。接口要求 `telegram:view`、`telegram:collect` 及当前账号数据访问权限，预览另需 `telegram:download`。

2026-10-25 验证：真实账号分 4 批读出 16 个频道，历史继续翻页无重复，原消息链接解析成功；9 项频道服务测试及 25 项采集服务回归通过。页面使用隔离响应验证目录/历史分页、单字搜索、频道/单条采集参数、图片/视频预览入口，以及 1920×911、1366×768、390×844 布局；本轮没有批量采集私人频道或重新下载全部媒体。

2026-10-25 频道工作区补充验证：14 项频道服务测试、25 项采集回归通过；真实频道图片/视频筛选首批各返回 20 条、链接 11 条、关键词 5 条、日期范围 13 条，核验类型、时间范围及继续翻页无重复。文件和音频在此样本无匹配。页面隔离测试覆盖独立页签、组合筛选、全选已加载、批量部分失败保留勾选及重试；批量提交只保存选中消息。三种测试尺寸未出现页面溢出。

## 极搜对话与结果类型

极搜不是 Mayday 直接调用的统一搜索 JSON API。服务端使用已授权 Telegram 用户会话向管理员配置的机器人发送关键词，并从 TDLib 更新中保存机器人消息正文、内容类型、按钮快照和安全的链接候选。机器人协议没有固定结构，因此未提供的字段不会被页面猜造。

搜索记录按 Mayday 用户创建的会话分组，左侧可新建、切换和删除多个会话。会话内容只对创建者开放，即使 Telegram 模块数据范围为全局，也不会共享个人对话；删除会话同时清理本地搜索及消息快照，不会删除 Telegram 机器人一侧的消息。仍在等待机器人回复的会话暂不能删除，避免迟到回复被重新写入已删除会话。

后台使用 `GET /api/telegram/conversations?page=1&size=50` 读取当前用户的会话摘要，使用 `POST /api/telegram/conversations` 新建会话，并通过 `DELETE /api/telegram/conversations/{id}` 删除。读取单个会话历史使用 `GET /api/telegram/conversation?conversationId=42&page=1&size=20`；创建搜索时在 `POST /api/telegram/searches` 请求体中传入所选 `conversationId`。返回体采用平台统一外壳 `ApiResponse<PageResult<ConversationTurnView>>`：`data.items` 是按搜索请求分页的对话轮次；每轮含 `search`（关键词、机器人、状态和时间）与 `messages`（该关键词明确关联的机器人回复）。每条回复保留完整的 `messageText`，并携带 `inlineLinks`（可点击文字的 UTF-16 起始位置、长度和安全 URL）；页面据此直接把机器人正文中对应文字渲染成超链接，文本、链接和换行仍保持原消息顺序。`sourceLinks` 继续作为保守识别的来源候选数据随该消息返回，不另行渲染成链接卡片。

典型响应如下。`replyMarkupJson` 是机器人按钮快照的 JSON 字符串；`inlineLinks` 精确对应正文里的可点击文字，`sourceLinks` 是同一条消息解析出的候选链接数据：

          "createdAt": "2026-10-22T16:33:00",
          "expiresAt": null
        },
        "messages": [
          {
            "id": 205,
            "telegramMessageId": "20031",
            "contentType": "MessageText",
            "messageText": "频道：iPhone 18 Pro",
            "replyMarkupJson": "[[{\"text\":\"🎬\",\"type\":\"CALLBACK\"}]]",
            "telegramSentAt": "2026-10-22T16:33:02",

            "inlineLinks": [
              {
                "offset": 3,
                "length": 13,

页面里“全部类型、群组、频道、视频、图片、音乐、聊天、机器人、文件”不是向某个假想媒体 API 传入的查询参数。Mayday 会先向机器人发送关键词，再根据机器人实际返回的内联回调按钮应用用户选择的类别；若该次回复没有给出相应按钮，页面保留原结果并明确提示。用户也可以直接点击某条回复中的分类或翻页按钮。`inlineLinks` 只把 Telegram 明确标记的链接实体或正文中可见的 HTTP(S) 地址做成行内超链接；不会改写或删掉原消息文字。`sourceLinks` 不等同于下载地址或官方结构化媒体记录。

按钮回调失败会按 Telegram 返回的安全错误类别给出操作提示；服务端日志只记录错误类别或 TDLib 数字错误码，不记录机器人按钮数据、原始错误文本或账号凭据。对于未知 Telegram 错误，页面提示刷新机器人回复后重试；具体外部根因需以更新版本后的实际请求日志为准。

已实现的媒体 HTTP 能力包括鉴权图片/文件内容，以及 MP4/WebM 的四小时短期播放票据与单 Range 流式读取。浏览器编码兼容性不足时，用户可排队生成 HLS 点播预览；服务器仅处理本地受控源文件，最多 2 小时、每预览最多 1 GiB 输出，并把清单/分片写入统一文件存储。HLS 的每个请求都重新校验 `telegram:download`、用户数据范围、父任务、原消息可保存状态及预览资产所有权；HLS 不包含加密密钥、外部 URL 或可从前端传入的文件路径。预览有跨实例租约、并发与空间预留、失败重试和自动留存清理。支持 MSE/HLS.js 的浏览器使用鉴权 HLS；其余浏览器可回退到受短期票据保护的原始 MP4/WebM 播放。当前 HTTP Range 仅支持一个字节区间。

已增加 ZIP/RAR/7z 按需目录浏览：权限需同时包含 `telegram:download` 与 `telegram:extract`。页面服务端分页列出最多 5,000 个目录项，并限制归档实际大小、目录声明总展开大小和单条提取大小。部署镜像提供 7-Zip；ZIP 由 Java 标准库读取，RAR/7z 由参数数组启动 7-Zip，无 shell 拼接，单文件提取到进程私有临时文件并在响应关闭后删除。条目名不会用作磁盘路径；拒绝路径穿越、符号链接、加密条目、分卷归档、递归提取及超限内容。支持识别的图片、MP4/MP4 兼容媒体预览和单字节区间请求。归档正文不会写入数据库。

Telegram 下载配额和自动保留清理由受保护的服务端环境配置控制：每个附件最大字节数、整个模块的保守存储预留上限、最低剩余磁盘空间、并发下载数、单次下载超时和保留天数。清理只处理到期且已经下载完成的媒体正文，使用数据库租约和幂等存储删除；失败记录会延迟重试，附件元数据仍保留。保留天数设为 `0` 时关闭自动清理。状态 `EXPIRED` 表示正文已清理，具备下载权限的用户可以从 TDLib 文件记录重新下载。

经用户授权，现已完成真实 TDLib 加密会话重启恢复、`@jisou2` 搜索/类型按钮/下一页、结果中的图片、视频和 PDF 采集与浏览器下载，以及同组相册和实际 HLS 转换验收。普通自动化测试仍使用隔离边界；真实联调单独记录于最新验收文档。机器人回复结构不是固定协议；系统保留原始消息及明确的链接实体，不承诺所有未知格式均可归一化。RAR/7z 已使用真实工具及官方小型 RAR 样例验证，不代表所有商业归档变体均通过兼容性认证。模块不承诺 Telegram 实时推送。

## 服务端配置

通过操作系统环境变量、受保护的部署密钥或项目现有配置注入机制提供以下配置；不要将真实值写入前端、提交到 Git 或粘贴到聊天中：

- `MODULE_TELEGRAM_ENABLED`：默认 `false`。确认凭据、密钥、持久目录和网络策略后才启用；沿用项目模块开关，重启生效。
- `TELEGRAM_API_ID`、`TELEGRAM_API_HASH`：Telegram 应用凭据。
- `TELEGRAM_SESSION_ENCRYPTION_KEY`：TDLib 本地数据库加密密钥，使用至少 32 个随机字节的 Base64 值并单独备份。
- `TELEGRAM_DATA_DIR`：受限访问的持久目录，默认 `./data/telegram`。该目录保存可恢复的账号会话，应使用受控操作系统账户和加密磁盘/备份。
- `TELEGRAM_SEARCH_BOT_USERNAME`：服务端允许联系的机器人用户名；必须由 Telegram 端验证为机器人后才允许查询。
- `TELEGRAM_PROXY_ENABLED`、`TELEGRAM_PROXY_TYPE`、`TELEGRAM_PROXY_HOST`、`TELEGRAM_PROXY_PORT`：Telegram TDLib 专用网络代理，默认关闭，支持 `socks5`、`http`、`mtproto`。代理认证由 `TELEGRAM_PROXY_USERNAME` / `TELEGRAM_PROXY_PASSWORD`（SOCKS5/HTTP）或 `TELEGRAM_PROXY_SECRET`（MTProto）注入。启用后会先由 TDLib 添加并启用代理，再提交账号参数；不使用 JVM、Maven、Git 或浏览器代理设置。状态页只显示协议和配置有效性，不回显地址或认证信息。
- `TELEGRAM_MAX_MEDIA_FILE_BYTES`：单附件可选上限，默认 0（不单独限制）。仍受可用磁盘和总存储容量约束；不再写死 50/512 MiB 上限。
- `TELEGRAM_MAX_STORED_MEDIA_BYTES`：已存正文与在途下载预留的模块上限，默认 10 GiB，允许范围 100 MiB–2 TiB。
- `TELEGRAM_MINIMUM_FREE_DISK_BYTES`：下载前必须保留的可用空间，默认 1 GiB。
- `TELEGRAM_MAX_MEDIA_WORKERS`：并发下载数，默认 2，允许范围 1–8。
- `TELEGRAM_MEDIA_DOWNLOAD_TIMEOUT_SECONDS`：单个 TDLib 附件下载超时，默认 7200 秒，允许范围 30–86400 秒。下载、校验和落盘过程中续租，防止大文件在 10 分钟后失去任务。
- `TELEGRAM_MEDIA_RETENTION_DAYS`：已下载正文保留天数，默认 90；`0` 禁用自动清理，最大 3650 天。
- `TELEGRAM_7ZIP_PATH`、`TELEGRAM_FFMPEG_PATH`、`TELEGRAM_FFPROBE_PATH`：归档/视频工具的可信服务端路径；默认分别为 `7z`、`ffmpeg`、`ffprobe`。生产 Docker 镜像自带对应 Linux 包，普通业务 API 不能修改可执行路径。状态页检查工具文件是否存在且具备执行权限，不会运行探测命令，也不返回服务器路径。
- `TELEGRAM_MAX_PREVIEW_OUTPUT_BYTES`：每个视频预览的 HLS 分片总量上限，默认 1 GiB，配置范围 16 MiB–4 GiB。
- `TELEGRAM_MAX_PREVIEW_DURATION_SECONDS`：单视频允许处理的最长时长，默认 7,200 秒。
- `TELEGRAM_PREVIEW_TIMEOUT_SECONDS`：单次 FFprobe/FFmpeg 处理总时限，默认 1,800 秒。

Windows PowerShell 可用系统密码管理器或随机数生成器生成密钥；输出仅在本机安全保存：

```powershell
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
[Convert]::ToBase64String($bytes)
[Array]::Clear($bytes, 0, $bytes.Length)
```

不要让多个应用实例同时打开同一 TDLib 会话目录。共享部署需要单实例调度和可靠文件锁策略。Linux 原生库依赖及 Windows VC++ 运行库要求以锁定的 TDLight 发行版说明为准；缺少运行库时不得因此影响模块关闭状态下的主应用启动。

## 授权与权限

在后台角色权限中按需授予 `telegram:view`、`telegram:configure`、`telegram:connect`、`telegram:disconnect`、`telegram:logout`、`telegram:search`、`telegram:collect`、`telegram:download`。`telegram:configure` 单独控制页面配置读取与保存；账号必须断开后才能修改连接参数。普通用户不会自动获得这些权限。账号所有者、平台管理员或具备显式全量权限的用户可管理账号；业务记录仍受所有权及现有部门/数据范围限制。下载任务入队时和实际取件时都会复核权限，媒体每次读取都会重新校验。`logout` 会远端退出并清除本机授权，必须与普通断开连接权限分开授予。

页面上的连接动作会根据 Telegram 要求提交手机号、验证码、两步验证密码或注册姓名。验证码和密码只在当前请求中使用，不写入业务表或浏览器持久状态。普通断开会保留加密会话以供恢复；退出账号会注销 Telegram 授权并删除本地会话。

## 运行和数据库

- 空库可导入单一脚本 `database/mayday.sql`（当前基线 V50，79 张业务表、806 个含注释字段），已有数据库使用 Flyway 增量升级 V35–V50；不得修改已执行迁移。
- Telegram 业务表、索引、外键和每列中文注释应同时存在于迁移与统一 SQL 中。运行 `node scripts/database-docs.mjs --check` 验证结构注释。
- 新增 Mapper 位于 `backend/mayday-telegram`，使用本地 MyBatis-Flex Starter；Telegram 不新增 JPA/Hibernate 数据访问。
- 查看环境状态：打开后台“Telegram”。模块关闭或配置不完整时，不会自动尝试登录、发送消息或联网搜索。
- Java 业务代码可以直接注入 `TelegramSearchService`、`TelegramCollectionService` 等服务；不得通过 HTTP 回调本机应用。

## 自动保留清理补充（2026-10-22）

- Telegram 媒体只在 `AVAILABLE` 且超过配置期限后进入 `DELETING`；下载中的附件不会被保留任务删除。数据库锁与 10 分钟租约允许多实例并行处理不同文件，并在进程中断后接管清理。

### 大文件与 4K 原始媒体

在 Telegram → 账号与连接 → 媒体下载设置中，选择“不限制单个文件大小”，并按磁盘容量设置总容量和单次下载等待时间。设置持久化到数据库，保存后新下载和显式重试使用新策略，不要求退出 Telegram。已有活动传输使用领取任务时的容量预留；降低容量不会截断已开始的下载。总容量不是单文件产品限制，磁盘不足、账号无权访问或消息禁止保存仍需明确报错。

大于 100 MiB 的原文件通过独立受限票据交给浏览器下载管理器，不再先构造整文件 Blob。支持 64 位 Range 偏移，原文件播放与下载保持原分辨率；浏览器不支持编码时的兼容转码仍有独立输出预算和画质策略，不代表原文件下载被限为低分辨率。新建的链接预览按需读取原视频，见下节；明确采集和兼容转码仍保留完整文件处理链路。

此前因容量限制失败的附件，在原预览窗口点击“重试下载”，不会重复创建采集任务或重新下载同组成功文件。下载票据与播放票据分开，均重新校验当前权限、数据范围及消息可保存状态，最长有效 4 小时。


### 按需在线视频预览（V53）

点击搜索结果的视频链接时，前端创建 `previewOnly=true` 且 `includeAlbum=true` 的有界预览。消息解析完成后，MP4/WebM 候选视频记录为 `REMOTE`，直接显示播放器；不会自动进入完整附件下载队列。明确点击“采集”仍保留原来的完整文件归档行为，旧采集任务的策略不变。

播放票据继续绑定单个媒体、有效期和当前权限；后端每次请求检查原消息可保存状态、任务来源及账号可见范围，验证实际二进制容器签名。HTTP Range 按播放位置读取，每次部分响应最多 1 MiB，支持尾部元数据与超过 2 GiB 的偏移。无 Range 的显式下载逐块输出，不在内存缓冲整段视频。底层使用 TDLib 的 [downloadFile(offset, limit)](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1download_file.html) 和 [getFileDownloadedPrefixSize](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1get_file_downloaded_prefix_size.html)，浏览器不获得 TDLib 文件 ID、账号凭据或本地路径。

按需播放仍需要网络传输及 TDLib 本地分段缓存，网络慢时会缓冲；它不表示零下载或保证任何视频都能秒开。播放保持原分辨率，编码不被浏览器支持时可选择缓存完整视频后进行兼容转换。若同一 TDLib 文件已有明确的完整下载在运行，分段读取不会取消它；尚未到达的区间可能需要等待或重新加载。已缓存的分段可复用，不自动删除其他任务使用的 TDLib 文件。

2026-10-25 针对性验证：真实公开视频 `durov/546`（10,837,502 字节，20.031 秒）以 REMOTE 状态在 Edge 播放并跳转至后段；请求返回 206，包含文件头、尾部及按播放进度读取的区间，播放后仍无平台完整存储对象；单独点击下载得到完整的 10,837,502 字节文件。服务重启后使用同一预览记录再次完成播放、拖动和下载，分段请求从原消息重新解析当前会话文件编号。另有 4 GiB 模拟文件的跨 2 GiB 偏移、无效区间、按需读取、关闭停止读取、错误容器拒绝及预览/采集队列隔离测试。真实 4K 大文件网络播放速度未在本轮测定。

### 频道消息内媒体展示（2026-10-25）

频道历史与查找结果直接显示图片缩略图、视频封面与播放按钮，附带文件大小和时长；文档和音频显示名称、类型、大小。点击卡片进入已有原图或视频预览。没有原生封面的附件显示附件卡片，缩略图读取失败时提供重试。

缩略图进入可视区域附近才读取，使用登录凭证且响应禁止缓存；切换消息、离开页面时取消请求并释放浏览器临时地址。浏览频道不会自动创建采集任务或下载整段视频。缩略图接口重新核对账号权限、频道成员资格及消息可保存状态，只返回图片字节，不返回 TDLib 文件编号或本地路径。2 MiB 上限只约束缩略图，不限制原视频大小或分辨率。

TDLib 将视频封面存于 `database/thumbnails`，普通媒体存于 `files`。适配层分别校验允许目录、真实路径和字节数；只有缩略图请求允许访问专用封面目录，普通附件下载及数据库文件访问范围不扩大。

### 首条搜索误收欢迎语修复（2026-10-25）

### 附件封面预加载（2026-10-25）
