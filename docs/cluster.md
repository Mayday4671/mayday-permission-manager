# 多实例与持久任务

本平台保持模块化单体，多个应用实例共享同一 MySQL 业务库。共享身份状态、刷新提示和持久任务不依赖额外 Redis 或消息中间件。此实现不替代数据库高可用、共享文件或生产容量规划；本轮真实两实例检查及未完成项见[完整功能记录](full-functions-validation-20261004/README.md)。

## 共享登录与配置

验证码挑战、一次性通过凭证、密码失败窗口和匿名反馈限流由 `SecurityState` / `JdbcSecurityState` 保存与原子消费。原始会话令牌和验证码通过凭证不存入共享状态，记录使用不可逆摘要；账户与连接来源的限额仍独立检查。重启不清空失败窗口，在 A 验证后可向 B 登录，重复消费被拒绝。固定状态配额与过期清理在数据库锁内检查，不能通过增加节点倍增限额。

系统参数直接读取共享数据库，成功保存后其他实例下一次查询即可得到新值。网站公开配置仍使用专用白名单 DTO；不能为同步配置把安全参数整体发给门户。OIDC 提供方是启动配置，所有实例必须一致，修改后统一重启。所有实例使用相同 `MAYDAY_IDENTITY_ENCRYPTION_KEY`，缺失或错误密钥会拒绝启动已有 MFA 凭据的系统，见[身份说明](identity.md)。

## 实时提示

`RealtimeJournal` 在原业务事务内保存接收者与 `messages/requests` 白名单主题，回滚不产生成功提示；提交顺序守卫避免高事件 ID 抢先提交造成游标漏读。各实例按独立游标读取已提交日志，连接仍只向已授权的当前用户发送。

共享连接配额为每账号四条、全站五百条；心跳延期本条连接，失效连接不能迟到续期，死实例配额三十秒后释放。撤销会话后其他节点的连接也会在重新鉴权时关闭。日志不包含正文或令牌，最多保留一天；这是刷新提示而非可任意重放的业务消息队列。客户端新连接与重连会重新查询持久未读和待办，十五秒轮询继续兜底。代理必须禁用 SSE 缓冲与缓存。

## 持久工作队列

`DurableTasks` 位于 `mayday-operations` 的 `cluster` 包。任务类型和稳定业务键唯一，重复提交相同参数得到原任务，不同内容使用原键会被拒绝。领取使用 MySQL `FOR UPDATE SKIP LOCKED`，随机租约令牌隔离旧工作器。时间来自数据库，`MAYDAY_TASKS_LEASESECONDS` 默认九十秒，允许十五至三百秒；不得把宿主机本地时钟当作租约依据。

工作器需在有界批次之间检查取消与授权，独立心跳保持租约。进程中断后其他节点可接管到期租约；旧工作器不能迟到续期或覆盖新任务状态。`fenced` 在持锁事务中执行业务提交并再次核验租约；`finish` 将结果与任务成功同事务提交。结果写入回滚时队列不能遗留成功。取消撤销当前租约，重试有上限；明确恢复重新排队，不暗中抹去失败原因。

业务副作用位于 MySQL 之外时，必须将稳定业务键传给外部接口或使用自己的幂等记录。HTTP 已发出、邮件已发送等动作不会随数据库回滚，此队列不保证任意外部副作用恰好一次。CPU 任务、外部请求还需要自己的超时和停止点，租约并不强制中断任意 Java 代码。

## 已接入的业务

用户异步导出通过持久队列执行，结果存共享 `sys_bulk_result`，各实例缓存使用原子文件发布，跨节点下载不需要粘性会话。执行和下载仍核查本人、字段授权与数据范围指纹；取消和重试只允许本人，见[批量数据](bulk-data.md)。

每个进程的 `MAYDAY_BULK_SPOOL_DIRECTORY` 必须独立，不能把导出缓存配置为共享卷。缓存目录在进程生命周期内持有 `.mayday-spool.lock` 的文件锁，同目录第二实例拒绝启动；进程被强杀后由操作系统释放锁，原实例可以重新取得。锁文件保留且不含业务数据或凭据，不要在运行期间删除它。共享的是 MySQL 中的结果正文，本地缓存可以重建。同一结果首次并发下载只生成一份完整缓存，正在读取的文件不会被清理；过期临时文件按数据库时间分批回收，并拒绝跟随符号链接。

注册式调度处理器使用同一持久领取边界和执行记录。手动触发携带幂等标识，同标识重复请求不重复执行；配置版本、当前权限、到期条件都重新检查。处理器业务结果与成功记录同事务提交，失败保持可查询记录与有界恢复；页面不执行任意 SQL、脚本或类名。

文件中心使用共享 S3 或共享 LOCAL 持久卷，不能给两个实例配置互不相通的本地文件目录。采集器仍有其专用持久状态与领取消费边界，保留原有停止、继续、重试语义；新增任务应明确自己属于通用队列还是专用引擎，不能两套工作器同时处理同一业务。

## 验证入口

`node scripts/verify-cluster.mjs <已构建的jar路径>` 在随机隔离数据库与两个 Java 进程中检查跨节点验证码/限流、配置、SSE、手动调度和导出，并强杀正在执行的导出工作器检查接管、三万行完整性及跨目录下载摘要。它还用真实 MySQL 验证并发领取、旧令牌隔离、结果回滚、重试上限和运行中取消。只清理本次拥有的进程及随机项目，不操作日常数据。

`node scripts/verify-native-baseline.mjs` 是 Windows 原生完整交付检查，覆盖空库、保留数据升级、唯一 SQL、业务与权限、持久身份和流程重启；Docker 镜像交付另用 `verify-baseline.mjs`。各验证结果只证明记录的产物与输入，不能将一轮本机检查当作跨地域容灾或高吞吐认证。
