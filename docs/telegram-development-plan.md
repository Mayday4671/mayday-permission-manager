# Telegram 模块开发计划

## 目标与边界

在现有 Spring Boot 应用中新增可裁剪的 `mayday-telegram` Maven 模块，复用后台会话、权限、MyBatis-Flex、MySQL/Flyway、文件存储和前端组件。首版使用平台管理员授权的一个 Telegram 用户账号；后台发起的搜索和采集任务记录发起人，后续读写都执行服务端权限和所有权校验。模块关闭时不初始化 TDLib、不触发网络请求、不影响其他模块，也不删除已有业务记录与文件。

`api_id` 和 `api_hash` 只从本机被忽略的 `.env` 或运行环境变量读取。授权验证码、两步验证密码、TDLib 会话数据库和加密密钥不得进入源码、数据库初始化脚本、浏览器持久存储、审计请求体或 Git。真实账号授权、向机器人发送搜索消息、创建采集任务和下载媒体都属于外部副作用；在实现并验收好界面后，由用户在本机页面主动触发。

## 已核对的工程事实

- 后端当前是 Java 21、Spring Boot 4.0.8；父 POM 管理 MyBatis-Flex 1.11.8 和 Netty 4.1.105.Final。
- `mayday-application` 是唯一启动模块；Flyway 位于应用模块统一管理，Telegram 账号表由 V36 创建；V37 只修复缺少关联的保留管理员授权。
- `ModuleSwitches` 负责菜单/API/权限同步裁剪；平台约定模块使用 `MODULE_*_ENABLED` 环境变量并在重启后生效。
- `docs/engineering.md` 要求统一使用 MyBatis-Flex、明确 DTO、Mapper 层 SQL、中文数据库注释、Spotless 与源码规范检查。
- AgentScope 模块已使用 MyBatis-Flex，可参考它的模块 POM、模块守卫和 controller/service 安全边界；其 JDBC 会话表不是 MyBatis-Flex 实体示例，Telegram 的业务表仍需遵守 EntityMapper/QueryWrapper 约定。
- 单一公开数据库脚本是 `database/mayday.sql`；增量升级继续使用新的 Flyway 迁移，不能改写历史迁移或对日常数据库手动执行 SQL。

## 版本与外部接口核验

TDLib 是异步客户端：请求响应、后续 update 和编辑消息必须分开处理。已从 TDLight 上游 release 页面核对到当前发布 `3.5.7+td.1.8.68`，其 Java API 和 native 版本由该发行 BOM 管理；Java 版本覆盖 17 至 21+，Windows x64 需 VC++ Redistributable，Linux 运行环境需 OpenSSL。上游使用 LGPL-3.0；打包交付时保留独立依赖、不修改其代码，并在用户文档和发行物中列明许可证及替换/获取源码方式。

- [TDLight Java 最新发布与 Maven 配置](https://github.com/tdlight-team/tdlight-java/releases)：版本、BOM、native classifier 与支持平台。
- [TDLight Java 官方仓库及许可证](https://github.com/tdlight-team/tdlight-java)：平台要求、原生库运行时和 LGPL-3.0 声明。
- [TDLight Java 示例](https://github.com/tdlight-team/tdlight-java/blob/master/example/src/main/java/it/tdlight/example/Example.java)：实际校验客户端工厂、凭据、会话目录和更新处理 API。

下一步实现必须以发行版源码/API 为准，在本机 Java 21 Windows 实际编译验证；不得凭记忆实现 API，也不得把控制台 `toString()` 当成官方 JSON 回复。真实 Telegram 联调与自动化测试分别记录。

## 计划评审与关键技术风险

- 总体范围与阶段顺序可执行：先确认宿主集成，再授权、搜索闭环、受限采集、媒体，最后处理归档和完整验收；外部账号操作留给用户主动发起，符合原提示词的安全边界。
- 当前授权生命周期实现采用低层 `TelegramClient`，避免发行版便捷封装把 `databaseEncryptionKey` 置空，并在 TDLib 参数中传入会话密钥。构建与无凭据拒绝路径通过，但构造 native 客户端会触发外部 TDLib 行为；因此必须在真实账号连接前完成隔离 native 客户端密钥传递与加密会话复用验证，不得仅凭代码宣称端到端加密已验收。
- TDLight `SimpleTelegramClient` 类有静态初始化逻辑，会加载 native。客户端及其工厂必须延迟到模块开启且管理员主动开始授权后再创建；关闭模块测试需要验证未触发 native 类初始化，而不只验证 HTTP 返回 404。
- TDLight 配置对象的 `toString()` 包含 API token。业务代码和日志不得记录配置对象、API token、TDLib 参数对象、验证码/密码或原始授权异常；异常需转换成脱敏状态后再记录。
- 阶段 2 的首个后续验收门是隔离客户端构造与密钥测试：确认可传入非空数据库密钥、等待验证码与两步验证时请求能异步完成、关闭不会调用 `logOut`、进程关闭能正常释放客户端。只有用户在本机主动完成 Telegram 授权后才能验收真实账号重启恢复；这之前继续完善阶段 2 的模拟状态和安全回归，但不得开始真实消息操作。

本次评审未对真实 Telegram 账号执行登录、发消息或采集；也未修改数据库。上述 TDLight 限制由所锁定发行版的官方源码核对：[参数初始化处理器](https://raw.githubusercontent.com/tdlight-team/tdlight-java/v3.5.7%2Btd.1.8.68/tdlight-java/src/main/java/it/tdlight/client/AuthorizationStateWaitTdlibParametersHandler.java)、[设置对象](https://raw.githubusercontent.com/tdlight-team/tdlight-java/v3.5.7%2Btd.1.8.68/tdlight-java/src/main/java/it/tdlight/client/TDLibSettings.java)、[客户端生命周期](https://raw.githubusercontent.com/tdlight-team/tdlight-java/v3.5.7%2Btd.1.8.68/tdlight-java/src/main/java/it/tdlight/client/SimpleTelegramClient.java)。

## ZIP 按需浏览实现（2026-10-21）

## 任务取消与媒体队列一致性复核（2026-10-21）

- 取消采集任务时，同一事务会将尚未开始的附件任务置为失败并清除租约，避免已取消任务留有可继续重试的排队下载。
- 对已经进入下载中的附件，发布存储对象前会重新读取父任务状态；父任务取消或已经不存在时，不发布对象并由下载流程清理临时存储对象。账号断线后，取消任务的媒体不会重新入队；用户重试媒体时也会再次检查任务未被取消。
- 新增采集取消联动与媒体发布/断线恢复用例。Java 21 下 `mayday-telegram` 及其必要依赖模块 Spotless 和测试通过，Telegram 子模块当前 31 项测试全部通过。
