# 生产部署与运行

本指南针对单组织、单应用实例的后台和客户门户。本文的启动保护、会话控制、数据库及文件恢复均有自动验证入口；域名证书、实际服务器容量和外部存储恢复仍需在部署环境验证。二次开发的资源接入步骤见 [复用指南](reuse.md)。

## 启动保护

正式部署设置 `MAYDAY_PRODUCTION=true`。应用在启动时检查以下配置，失败直接退出，错误只显示配置名称，不输出密码：

- `DB_PASSWORD` 与 `ADMIN_PASSWORD` 至少 16 位，不能使用仓库中的示例密码；应使用独立生成的随机凭据。
- 数据库运行账号不能是 `root`。
- `SEED_DEMO_DATA=false`，`API_DOCS_ENABLED=false`。
- `MAYDAY_PUBLIC_ORIGIN` 必须是 HTTPS 站点来源，如 `https://portal.example.com`，不能包含账号密码、业务路径、查询或片段。
- 已有库中的 `admin` 不能仍使用公开示例密码。修改 `.env` 中的初始密码不会重置已有账号，请先通过正常账号管理完成密码轮换。

`MAYDAY_PUBLIC_ORIGIN` 是部署声明，不会替代证书配置或改变浏览器入口。容器默认只绑定本机回环地址；对外入口应由部署方配置 HTTPS 代理，数据库保持内网隔离。当前登录来源按实际连接地址计算；未实现任意代理头信任，不能仅添加客户端可伪造的 `X-Forwarded-For` 就当作真实来源。生产多实例需先替换进程内验证码、限流和事件分发，当前验证不覆盖集群。

## 分离迁移与运行账号

本地默认 `DB_MIGRATIONS_ENABLED=true`，应用账号同时负责迁移与运行。正式环境可以分两阶段：

1. 停止旧业务写入，完成数据库与文件备份；使用独立迁移账号运行同版本应用的 Flyway 迁移，确认结构与校验和一致。
2. 结束迁移任务，业务服务改用只具备业务库 `SELECT/INSERT/UPDATE/DELETE` 权限的运行账号，设置 `DB_MIGRATIONS_ENABLED=false`。Hibernate 仍校验结构，不自动创建表。
3. 检查就绪探针与正常业务读写，再切换入口。不能删除 Flyway 历史或关闭结构校验来跳过迁移错误。

真实验证脚本在独立数据库创建迁移账号和仅 DML 运行账号，验证首次初始化、迁移关闭后的重启与读写。已有版本升级还应保留 `flyway_schema_history` 的读取权限；它包含在业务库 SELECT 授权内。

## 会话期限与登录数量

服务端会话默认固定期限 720 分钟、无认证请求期限 30 分钟、每账号最多 5 个有效会话。环境配置为 `MAYDAY_SESSION_ABSOLUTE_MINUTES`、`MAYDAY_SESSION_IDLE_MINUTES`、`MAYDAY_SESSION_MAX_PER_USER`；范围分别是 5–10080 分钟、1–固定期限、1–20 个，错误配置拒绝启动。

无请求期限由真实认证请求刷新，后台轮询也算请求活动，因此它不是键盘鼠标空闲锁屏。固定期限不会续期。修改期限后，较短配置会约束已有会话，较长配置不会延长签发时已保存的到期时间。并发登录按数据库账号行锁串行签发，达到上限时撤销最早有效登录；失效会话不会被首次访问重新激活。

在线会话的搜索、授权范围、有效期限过滤、总数和分页都在 SQL 中执行。页面“预计失效”显示当前规则算出的最早期限。每次认证重新读取账号及角色，退出、密码修改、停用和强制下线均沿用现有撤销规则。期限与服务端撤销原则参考 [OWASP 会话管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)，本项目未声称完整 ASVS 或身份平台认证。

## 探针、错误定位与更新

`/actuator/health/liveness` 只反映应用进程状态，`/actuator/health/readiness` 包含数据库连通状态；匿名响应不公开组件详情。数据库中断时，存活探针仍为 UP，就绪探针返回 HTTP 503，部署平台据此停止分配业务流量，不应仅因数据库故障反复重启应用。行为参考 [Spring Boot 探针说明](https://docs.spring.io/spring-boot/4.0/reference/actuator/endpoints.html)。其他 Actuator 端点没有因此公开。

每次请求由服务器生成 UUID 格式的 `X-Request-ID`，忽略客户端指定值；日志写同一关联号，不记录正文、查询参数、密码或原始令牌。前端服务异常显示定位号，便于查同次请求。代理直接拒绝的上传错误可能没有应用定位号，但显示明确的大小提示，不把 HTML 错误页展示给客户。

应用支持最多 30 秒的正常停机等待。更新时停止业务写入并备份后再启动新服务；服务重启时 SSE 客户端重连，轮询作为刷新恢复路径。Nginx 的 SSE 地址禁用缓冲与缓存，哈希静态资源长期缓存，入口文档重新验证，不存在的脚本返回 404。

## 文件与恢复点

单文件默认上限 10 MB，后台配置可在 1–100 MB 调整；应用最大请求和默认 Nginx 请求上限均为 101 MB，为 multipart 请求预留空间。不能只调页面限制而忽略外部代理的上限。文件上传、缩略图和下载仍执行所属业务权限；大小配置不是访问授权。

LOCAL 文件位于持久卷 `/app/data/files`；数据库只保存引用，备份数据库不能恢复这些正文。`scripts/upgrade-local.mjs` 停止业务写入后同时生成 SQL 和 LOCAL 目录副本，并记录每个文件的长度与 SHA-256。恢复时必须使用同一恢复点的数据库与文件，核对完整清单；在隔离目标容器中恢复并给予应用 `mayday:mayday` 读取权限，通过鉴权下载与缩略图读取后再切换入口，详见 [升级与恢复](upgrade.md)。

旧 MYSQL 文件正文随 SQL 备份保留。S3/MinIO 文件不包含在本地目录备份中；应另外配置对象版本、受控备份和恢复测试。当前文件恢复回归只验证 LOCAL，不能将其视为外部对象存储容灾已经通过。

## 验收与变更门槛

`node scripts/check-project.mjs` 检查源码注释规范、格式、契约一致性、交互回归、类型与生产构建；`node scripts/verify-baseline.mjs` 检查隔离升级库、迁移空库、唯一 SQL 导入库、真实权限与业务接口、文件恢复及生产启动规则。Java 单元与集成检查使用 `backend/mvnw verify`。

验收结果记录当前源码、配置模板和测试脚本的内容摘要，包括未提交的新文件。升级脚本在构建前及构建后校验摘要，变化或缺少摘要的历史记录不能作为发布依据。真实 `.env`、备份、构建输出和截图不混入源码摘要；部署方仍需独立核对实际环境变量。页面外观及完整交互另做浏览器验收，自动检查通过不替代用户体验和生产容量验收。
