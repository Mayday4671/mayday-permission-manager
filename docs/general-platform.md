# 通用平台能力与扩展方法

本轮能力服务于单组织后台与客户内容门户，保留单侧分组菜单、多标签页、业务弹窗和独立前台主题。历史代码与新增代码使用同一套格式和注释检查，UDP 只整理源码规范，不扩展转发业务。

## 文件中心

文件保存通过 `FileStorage` 接口，业务代码不拼接磁盘路径或对象地址。新增上传默认使用 `LOCAL`，Docker 的 `file_data` 数据卷持久保存 `/app/data/files`；文件元数据、所有者、目录、回收状态仍在 MySQL。历史 `MYSQL` 文件继续读取，采集模块保留原数据库写入方式，避免在本轮改变其事务补偿语义。切换配置不会搬迁已有文件。

设置 `.env` 的 `MAYDAY_STORAGE_MODE=S3` 后配置 `MAYDAY_STORAGE_S3_ENDPOINT`、`MAYDAY_STORAGE_S3_REGION`、`MAYDAY_STORAGE_S3_BUCKET`、`MAYDAY_STORAGE_S3_ACCESS_KEY` 和 `MAYDAY_STORAGE_S3_SECRET_KEY`，重启后生效。兼容存储使用路径式访问。访问密钥只在服务端环境中读取，不包含在页面响应和日志里。桶应事先创建且保持私有；使用 HTTPS 和满足部署环境要求的备份、凭证轮换策略。

文件中心支持个人目录、图片缩略图、批量移动、回收站、恢复与永久删除。目录名称、层级、版本和所有者均在服务端检查，批量操作先校验全部文件再修改，混入无权文件不会部分执行。业务附件引用保护覆盖内容修订、通知、审批与采集：已被引用的文件不能回收或永久删除；回收文件不能添加为新附件。缩略图和下载共用授权，不暴露磁盘路径和存储密钥。

上传失败回滚时补偿外部对象；永久删除交给持久待删除状态与后台清理。外部存储删除失败保留元数据重试，不把失败当作成功。多实例使用共享 S3，或为 LOCAL 提供共享持久卷；不同实例的独立磁盘不能互相读取。单文件默认限制 10 MB，可通过 `MAYDAY_STORAGE_MAX_MB` 调整到 1–100 MB。

## 实时消息与审批

登录后的 SSE 用请求头携带现有会话令牌，不将令牌放入 URL。连接按用户隔离，发送及心跳重新验证身份；撤销某个领域权限后不再推送该主题，全部订阅权限或会话失效时断开。业务事务提交后再发刷新提示，事件只有主题与时间，没有业务正文。前端刷新真实待办和未读查询，断线重连，并用轮询兜底，事件不代替数据库记录。

审批支持申请人或具备独立管理/催办权限的审批管理员催办，以及节点超时提醒，重复催办有 30 分钟间隔。流程节点可配置 1–43200 分钟的办理时限，发布版本保存配置快照，转交及加签继承原截止时间，避免通过操作延期。超时提醒按待办去重，已经处理的任务不会继续提醒，也不自动代替审批决定。常用流程模板复制为可修改的草稿，仍经过字段、节点、参与人和发布校验。

当前事件总线是单实例内存分发；多实例需要共享消息总线，将提交后的事件发送到接收者所在实例。数据库持久通知和前端轮询可恢复漏过的即时事件，但不应将此描述为集群实时推送已经完成。反向代理应允许流式响应，避免缓存 SSE。

## 表格与导入导出

公共 `DataTable` 提供序号、列宽与顺序、显隐、密度、账号/页面偏好、手机卡片和主题边框。当前视图 CSV 和打印只处理已经显示、已获授权的数据，不额外拉取全站数据。页大小按可用空间调整；列内容按规则省略并保留完整值查看，不用默认横向滚动掩盖布局问题。

服务端导入导出通过注册的 `BulkResourceAdapter` 扩展。目前用户模块提供 CSV 模板、预览、逐行错误清单、原子提交和异步导出。新增资源必须明确可导入字段、独立动作权限、角色委托限制、数据范围以及导出字段，不能把数据库表名或任意 SQL 当作前端参数。导入密码只参与创建用户，不保留原 CSV；幂等校验使用带盐慢哈希，不存可用于快速猜测密码的文件摘要。

导入先预览，提交时重新校验当前权限、字段和数据，不信任浏览器预览结果。任意一行不合法时全部回滚，同一幂等标识同时提交也只生成一次结果。异步导出提交、执行、下载均重验当前授权，作业与文件只允许发起者读取，管理员也不能直接领取他人的导出。导出权限撤销后禁止下载；后台清理过期临时文件，重启中的作业明确标记失败。

具体接口、限制和扩展示例见 [批量数据交换](bulk-data.md)。

## 调度与监控

实现 `JobHandler` 并注册为 Spring Bean 即可添加固定处理器。页面只选择已注册的标识；禁止任意 Java 类名、SQL 和脚本。内置数据库检查与会话清理可直接使用。自动任务在事务内锁定配置并重验到期时间，执行日志独立于请求日志。

处理器失败时先回滚业务事务，再以独立事务保存 `FAILED` 记录并推进下次执行时间，调用方的外层事务回滚也不会抹去该记录。失败站内提醒在记录提交后发送，提醒发送失败不丢失执行日志；最近一天的待发失败按最早记录分批重试，已投递条目退出队列，避免积压超过 100 条时永久漏发旧提醒。消息关闭时保留待发状态；未配置或失效的接收人明确跳过，之后恢复权限不会补发这些历史提醒。

默认数据库事务限时 30 秒，适合短任务；它不等同于强制中断任意 CPU 运算或外部调用。长任务应提交到自己的持久工作队列。失败回滚至失败记录提交之间存在领取间隙，外部副作用也不随数据库回滚；扩展处理器必须在业务层保证幂等，不能宣传外部任务严格执行一次。

监控每 30 秒采集当前进程的内存、CPU、线程及数据库延迟，保留 7 天；页面查看当前节点最近 5–60 分钟的有限数据。进程重启后从新节点序列开始，不拼成连续假趋势。采样先独立提交，提醒发送失败不回滚趋势；消息与提醒冷却时间在后续事务中共同提交，失败可随下次真实采样重试。堆内存与数据库延迟阈值默认关闭，开启后每 30 分钟最多提醒一次。数据库断开时，不能向同一故障数据库保存采样或告警；生产环境的存活告警应由外部监控承担。

## 客户反馈

门户提供问题、建议和内容纠错，提交后返回一次性展示的随机查询码。查询码不进入 URL，数据库只保存其哈希；客户凭码看到状态和公开回复，看不到联系方式、内部备注、处理人和后台入口。查询码丢失后没有匿名找回功能，应自行保存。

后台查看、处理、分配分别授权；处理与版本校验受事务保护，解决反馈必须有公开回复。每次处理保存轨迹，通知模块启用时分配产生站内提醒。当前后台反馈为共享权限，尚未按部门或租户划分处理范围。匿名提交与查询按连接来源限流；当前限流器为单实例内存，代理部署需在受信入口配置来源处理，多实例需共享限流服务。

## 变更审计与代码规范

变更记录展示用户、角色授权、内容发布等操作的可读前后差异，与 HTTP 请求日志分开。差异按显式允许的字段生成，排除密码、令牌、联系方式、正文和存储秘密；与业务修改在同一事务中保存，回滚不留下成功变更。

`node scripts/check-source-conventions.mjs` 使用 Java/TypeScript 语法树检查显式导入、公开业务边界注释和手写前端 `any`。类注释说明职责，方法注释说明权限、状态、事务与失败语义。Java Spotless 与前端 Prettier 负责统一格式；公共组件和生成器采用相同标准。不要用重复代码的空话补足注释。

数据库公开交付仍只有 `database/mayday.sql`。本篇通用能力批次验收到 V19，保留 V1–V18 历史校验和，V19 后续也不能改写；当时三种安装路径核对一致为 48 张业务表、471 个字段、121 个索引（含主键）及 45 个外键，不计 Flyway 自身历史表。后续 OA 完善已追加 V20，门户栏目与首页控制追加 V21；当前基线为 V21（51 表、506 字段、128 索引及 48 外键），下一份迁移从 V22 开始。历史批次结果保留原口径，新增能力见 [OA 流程指南](oa-workflow.md)及 [门户说明](portal.md)。旧库用新 Flyway 迁移升级，不重导初始化脚本；新表、字段、枚举、单位、空值和关键约束均应有中文 COMMENT。

## 验收与部署

运行 `node scripts/check-project.mjs`、后端 `verify` 和 `node scripts/verify-baseline.mjs`。基线脚本在隔离项目验证原库恢复升级、新库安装、统一 SQL 导入、表/字段注释及索引/外键语义、真实 HTTP 权限/并发/失败/清理、模块关闭与契约，不能把测试指向日常业务库。真实 S3 验证单独使用测试桶与短期服务，凭证不提交。

最新证据见 [本轮通用平台验收](general-platform-validation-20261002/README.md)，旧截图及旧测试结果不能自动代表新版本通过。二次开发仍需补自己的业务边界、备份恢复、上线配置和集群方案；可复用底座不代表任意新增业务无须验收。当前未集成恶意文件扫描、超大文件分片续传或可跨节点恢复的长任务平台。
