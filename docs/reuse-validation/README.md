## 结论范围

这套系统具备单组织后台常用的权限底座：服务端动作授权、角色按资源的数据范围、用户联系方式读写隔离、授权委托限制、可撤销会话、内容发布边界及审批参与/字段/动作校验。可复用为后续业务系统的基础工程；新模块仍必须接入权限目录、动作校验与数据范围，不能认为复制页面就自动安全。

本次参考 [OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)进行针对性检查。没有完成 [ASVS](https://owasp.org/projects/asvs) 全部条目验证，不宣称标准认证或不存在其他漏洞。多租户、统一身份、MFA、多节点共享限流与缓存、外部防篡改审计及容量验证的限制详见 [复用指南](../reuse.md)。

## 检查及修复

- **服务端权限**：核查 SecurityConfig、TokenService、AccessPolicy、用户/角色及通用资料接口、跨模块人员选择、文件、内容公开、通知和审批入口。默认认证与每个资源动作检查共同执行；已登录零权限账号不能进入管理数据查询。
- **旁路用户总数泄露（已修复）**：DATABASE_CHECK 调度结果原来返回 users.count，使 scheduler 权限间接得到全站用户数。改为只报告连接成功；真实 HTTP 测试同时验证即时结果和执行历史。
- **点击劫持保护（已补充）**：前端 Nginx 原来没有禁止其他站点嵌入页面。增加 CSP `frame-ancestors 'none'` 与 `X-Frame-Options: DENY`，不改变 Ant 组件的动态样式能力。
- **初始化复用（已补充）**：空库默认只创建管理员和必要基础资料；显式 `SEED_DEMO_DATA=true` 才加入演示组织、角色、成员与文章。已有数据不因开关变化被清理或重复添加。
- **扩展耦合（已修复）**：角色范围白名单、会话摘要和角色页面原来固定 users/notices，现在统一从 PermissionCatalog 的 scoped 标记派生；新业务仍需选择正确的实体所有者/部门字段并调用过滤策略。
- **权限展示（已修复）**：角色没有资源 view 权限时，列表显示“未授权”，不再把没有生效的部门范围展示为实际权限。最终页面及编辑弹窗已实测，未保存或修改日常角色配置；[截图](roles-scopes.png)。
- **数据库说明（已补齐）**：此前 35 张业务表的 301 个字段没有数据库 COMMENT。新增 V12 覆盖全部表/字段，说明用途、状态、NULL、关系和兼容字段；V1–V11 原文件不变。验证每个字段的类型、默认值、NULL、自增及排序规则不变。
- **验收工具（已修复）**：数据库客户端显式使用 utf8mb4，避免中文注释在校验输出中变成问号；主题测试恢复原始参数行、版本和时间，并移除其新建的测试行，避免只恢复外观却改变业务快照。

## 可复用能力和实际边界

- 普通 RBAC、按本人/部门/下级/指定部门/全部的数据范围，以及 SQL 查询与单条读写共用边界已经实现。角色范围取并集，没有显式 deny 规则；共享部门/分类/角色目录按模块授权，不是所有表都做部门隔离。
- 密码 BCrypt、随机会话令牌摘要存储、密码变更/停用撤销会话、每请求重新加载有效授权及登录失败限流已经实现；限流为单进程内存实现，没有 MFA/SSO 和敏感动作二次认证。
- 用户邮箱/电话和审批字段具有独立细粒度约束；不是任意新业务字段都能无代码配置权限。
- 审计记录写操作及导出结果，不保存敏感请求正文；不具备外部防篡改审计及任意业务对象完整 before/after 差异。
- 内容发布与审批修订绑定、收件人私有投递、附件业务鉴权已经实现；不包含完整 BPMN、多租户、外部消息、文件病毒扫描或对象存储。
- 前端生产依赖 `npm audit --omit=dev` 返回 0 个已知漏洞；该结果仅代表当次注册表数据和生产依赖集合，不是后端依赖、开发依赖、基础镜像或完整供应链扫描。
