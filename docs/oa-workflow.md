# OA 流程使用与扩展

本轮从可配置审批升级为可完整办理的 OA 流程。保留现有模块、菜单、页签、业务弹窗、主题和不可变发布版本；不改写历史申请，也不通过更换模板绕过旧实例的字段权限。

## 验收范围

- 设计：表单控件、字段顺序/布局、字段说明、日期时间/日期区间/明细表；节点连接图、审批/抄送/条件/结束、人员来源、会签/或签/顺签、字段权限、版本与发布校验、预览模拟。
- 发起：本人草稿保存与继续编辑、提交校验、流程及人员快照、重复提交与旧版本保护。
- 办理：同意、终止性驳回、退回申请人修改、退回当前实际路径中已办理的审批节点；撤回、修改重提、转交、加签、评论、催办、管理员终止。
- 展示：待办/已办/我发起/我参与/抄送、状态过滤、运行轮次与节点办理批次、办理轨迹、当前节点和可退回目标、抄送已读。
- 安全：每次执行重新校验身份和权限；回退后取消旧待办，后续轮次不能使用旧审批结果；未来节点和其他申请的草稿不可读；附件和审计沿用字段权限。
- 场景：请假（日期区间）、报销（明细与金额）、采购（条件分支），覆盖多次退回/重提、顺签/会签/或签、撤回与并发决定、发布新版不改变在途申请。

## 原有问题与本轮修正（2026-10-02）

实屏已查看流程列表、设计器、节点编辑、表单设计和申请入口；本机没有已发布可发起的业务流程，因此运行行为使用新建的隔离验收数据检查，不向日常库塞入测试申请。

1. 驳回直接结束，没有退回与修改重提状态；没有持久申请草稿。
2. 节点按卡片排布，连接关系缺少直观图示；可读/可写字段用长多选控件。
3. 表单缺少日期区间、日期时间和业务明细；没有抄送、顺签。
4. 打开节点弹窗后未修改也出现丢弃提示，程序初始化与原始值快照存在时序问题。

上述问题已落实到模型、服务端执行、前端操作和数据库迁移中；原始截图保存在本机 `.local/oa-audit/`。最终验收记录与本指南分别维护，避免把功能实现等同于全部验收完成。

执行引擎的结果见 [OA 流程验收记录](oa-validation-20261002/README.md)：升级库与新建库各 135 项真实接口检查通过。2026-10-03 重新设计节点添加与分支编排，见 [流程设计器验收](oa-designer-validation-20261003/README.md)；随后重做表单三栏交互，并在隔离后台通过真实保存、发布、填写、退回申请人、修改重提及同意结束的浏览器链路，见 [表单设计验收](oa-form-validation-20261003/README.md)。其他多人、条件和并发场景仍以相应接口回归为证据，不冒充本次浏览器办理覆盖。

## 设计与发布

1. 在审批分类中配置业务分类，在流程定义中从请假、报销、采购模板创建，或创建空流程。模板只生成可编辑草稿，不自动选择其他部门人员、不自动发布。
2. 表单设计采用“控件库／编排画布／字段属性”三栏：左侧搜索、点击或拖入控件，中间选择、排序和复制字段，右侧即时修改标题、必填、宽度及类型对应属性。普通编辑不提供字段 ID 或类型切换；更改显示名称不会破坏节点字段权限与分支引用。窄屏将控件库、属性面板分别放入弹窗，修改直接进入本地草稿，“完成”仅关闭弹窗，不另保存字段。
3. 流程设计从“发起人”向下展开。在线路的“＋”选择审批人、抄送人、条件分支、并行分支或子流程，自动插入该位置并保留后续流程；点击节点卡片打开人员、字段权限和办理设置弹窗，日常操作无需填写节点 ID、类型或手动选择出口。分支中的加号仅修改该分支；汇合后的加号为各分支添加一份共同后续节点。
4. 每个审批节点配置人员来源（指定用户、角色成员、发起人部门负责人），选择会签、或签或顺签。字段矩阵逐项设置隐藏、只读、可编辑；可编辑必然包含可读。抄送节点仅支持隐藏、只读，不提供审批动作。
5. 保存草稿后先运行校验和模拟，再发布。服务端检查字段和类型、所有分支的节点引用、可达性、循环、人员、字段授权和动作，失败不会发布。模拟只计算预览，不创建真实待办。

发布版本不可修改。编辑和再发布生成下一版本；已经提交的申请继续使用提交时的版本、字段和节点，不能被后来的流程草稿修改。新版发起范围收回或流程停用后，旧申请仍可办理，退回后的重提会重新检查当前流程是否允许该申请人发起。

### 节点与分支操作（2026-10-03）

- 添加条件分支会展开一条显式条件和“其他情况”。点击条件卡片配置表单字段、比较方式及比较值，新增条件后也逐条配置。从左到右匹配第一个满足的条件；均不满足走其他情况，不是并行执行。
- 使用条件卡片的左右按钮调整优先级。“其他情况”始终保留、位于最后；删除最后一条显式条件需删除整组条件，不能产生无兜底分支。
- 数字、金额和计算结果可以比较大小；单选的等于、不等于使用原表单选项，“包含”直接填写子串，不要求子串也是完整选项。数值“包含”同样直接输入文本，保留 `.00` 等表示；其他数值比较采用精确十进制。日期和日期时间使用对应输入控件。AND/OR 分组最多三层、每个分支最多 20 条判断；优先级和默认路线保持原有语义。明细表本身不直接比较，可通过汇总后的计算字段判断。并行分支是独立节点，不借条件多选模拟并行。
- 删除普通节点会把所有前驱连接到原后继。删除条件组保留默认路线，清理其他分支独有节点，保留公共后续；删除前有确认，确认后可以撤销。正在引用的结束节点不能删除。
- 新节点的属性弹窗取消后，节点仍留在本地草稿，未配置项会提示；撤销或删除才能移除插入。草稿允许未填完，但人员或条件未配置时服务端禁止发布。
- 撤销、重做保留最近 30 次本地编辑；后续编辑清空重做。它们不会撤销服务端已发布版本。缩放及“适应画布”只改变浏览范围，长流程允许在画布内正常滚动。
- 加号、节点和分支操作均可通过键盘访问。打开加号后焦点进入选项，Escape 关闭并回到原线路；弹窗继续使用共用表单提交和离开保护。
- 旧草稿的损坏连线、循环或孤立节点明确提示并提供专门修复入口；正常编排不显示手动连线选择。不同结束路径按原图显示，只有各路径必经的节点才画成汇合。复杂交叉图按预算展开并可切换完整连线查看，不为排版而改写模型。

交互参考 [飞书官方审批流程设计说明](https://www.feishu.cn/hc/zh-CN/articles/360036163653-%E7%AE%A1%E7%90%86%E5%91%98%E8%AE%BE%E8%AE%A1%E5%AE%A1%E6%89%B9%E6%B5%81%E7%A8%8B) 中的节点间添加与横向条件分支方式；此实现使用本项目已有运行引擎和权限契约，不承诺参考产品的全部能力。

### 表单编排与试填（2026-10-03）

- 控件库按基础、选择、其他控件分组。点击控件会添加到末尾并选中；拖到已有字段上会插在该字段之前，拖到末尾区域会追加。拖动已有字段改变其顺序；上移、下移按钮及 `Alt + ↑ / ↓` 提供同样操作。外部网页、文本或文件拖入不生成字段，也不上传文件。
- 画布选择字段后在右侧立即编辑属性，无需先打开字段属性弹窗或逐项保存。标题、输入提示、填写说明逐字更新本地草稿；输入框保持焦点。空标题、重复或空选项、非法上下限等暂时编辑状态会定位提示，保存与发布前必须修正，服务端仍执行最终检查。
- 字段支持整行、半行；手机尺寸展示采用单列。桌面、手机按钮只是查看当前表单的布局，不向模型写入设备信息或实际窗口尺寸，也不保证未经实测的每个设备布局均通过。
- 复制字段紧邻原字段插入，生成未占用的主字段 ID，选项和明细列深拷贝。副本不自动获得原字段的节点读写权限，分支条件也不会切换到副本。新字段和副本需在各节点单独授权。明细列 ID 只在所属明细表内唯一，不同明细表中同名列不冲突。
- 删除字段先确认；仍被条件节点引用的字段禁止删除，需先调整分支。普通字段删除会清理草稿节点中相应的可读、可写引用；已发布版本和已提交申请不受影响。调整标题、布局或位置时不改旧字段 ID、控件类型、节点权限及连线，不按字段名称重新生成引用。
- 单选的 `EQ / NE` 条件使用原始选项值。改名或删除被条件使用的选项后，会提示对应字段与条件节点，并阻止保存、发布，需在流程设计中明确修正比较值；不自动替换条件，不静默 trim、去重或过滤选项。`CONTAINS` 仍允许比较选项的子串。
- 撤销、重做由流程设计器统一维护最近 30 次本地编辑。相同字段的连续属性输入合并记录；结构操作、不同字段的编辑分别记录。撤销保留原 ID 与旧属性，不影响服务端已经发布的版本或在途申请。离开时的未保存提示仍由共用保护处理。
- “填写预览”使用实际申请控件，支持必填、文本长度、数值范围、十进制精度、有效日期、日期区间、选项与明细子列校验；“检查填写”“清空填写”只操作临时试填值。更换模型或重新进入预览会清空旧试填值，不把其写入草稿、模拟申请、待办或业务记录。
- 编排画布只展示人员、部门、附件控件外观，选择字段不查询通讯录、不上传附件。填写预览的人员、部门控件可按当前账号已有权限查询实际可选项；附件上传禁用，不支持借预览生成真实文件。人员存在性、附件归属及流程授权最终仍由实际提交接口校验，前端“检查填写通过”不等于获得业务授权。
- 只读账号可查看字段及明细列属性、切换尺寸与试填，不允许通过按钮、属性事件、快捷键或拖放改变模型；保存、发布继续分别校验各自权限。Java 旧模型中未配置的 `null` 数值按缺省理解，未编辑属性和未知扩展属性原样保留，不在加载或布局时自动归一化。
- 损坏旧草稿中的重复主字段 ID、重复明细列 ID 会明确报错，不能通过一次属性编辑覆盖多项或按重复 ID 批量删除；明细列属性与编排写入暂停，需先修复旧配置。不会为使界面可编辑而擅自重编号或改变已有条件、权限引用。

以上说明记录当前实现与操作边界；真实浏览器整页保存、发布及办理的验收状态以对应验收记录为准，不能仅凭组件回归或接口测试标记完成。

## 表单能力与限制

- 支持文字、多行文字、数字、金额、计算字段、日期、日期时间、日期区间、单选、多选、人员、部门、附件、明细表，共 14 类控件；支持必填、输入提示、填写说明、文本长度、数值上下限。
- 明细表支持 1–6 列、最多 1–50 行（默认 20）。右侧属性中选择当前列，逐列编辑标题、必填与类型对应约束；支持添加、上移、下移、删除，不能删除最后一列。新列可选择文字、多行文字、数字、金额、日期、日期时间、单选，自动生成未占用的稳定列 ID；旧列 ID、类型不直接改写。单选列和主表单的选择控件一样逐项输入、增删与排序，不使用整段换行文本。列的必填与数值/长度/选项约束由服务端逐行校验。明细不嵌套明细、附件或人员选择器。
- 字段及列标题为 1–60 个字符，输入提示最多 200，填写说明最多 500；文本长度配置为 1–10000 的整数，未配置时运行校验默认最多 2000 个字符。单选、多选需要 1–50 个不重复的非空选项，每项最多 100 个字符，保留原始值与原始空格；数值下限不能大于上限。
- 表单画布按窗口剩余高度分配空间，页头换行、主题密度及侧栏宽度改变后重新测量；长表单在编排区内正常滚动。极矮窗口保留最小操作区域，不通过隐藏内容强行消除所有滚动。
- 刷新、登录返回及页签切换保留合法流程编号；恢复目标只保存页面与正整数实体参数，不存储表单、试填值或登录凭证，服务端仍核对每次实体访问权限。
- 日期区间要求开始不晚于结束；日期时间当前采用服务端业务本地时间，不是跨时区时间戳。金额以十进制比较，数值条件的 `0` 与 `0.00` 相等。
- 单流程最多 40 个字段、40 个节点。条件支持已有简单字段的比较和按顺序匹配，不把日期区间、明细等复杂对象转换为字符串比较。
- 附件沿用文件中心的账号、所属数据及字段授权；历史轮次使用过的附件保留引用，下载仍重新检查读取权限。

计算字段通过右侧属性配置求和、顺序减法、乘法、顺序除法、明细数值列汇总或日期区间天数，结果只读。计算字段可引用其他计算字段，但发布时拒绝循环、缺失来源和不适用类型；被引用字段不可直接删除。草稿缺少输入可保留空结果，提交时检查必填结果、除零和数值范围。金额按十进制四舍五入，日期天数包含起止日期，不自动扣除节假日。

当前验收仍有明细列身份问题待修：删除 DETAIL_SUM 引用列后，自动列 ID 可能被新列重用而静默改变汇总来源。已有服务器模型校验不代替编辑器引用保护；修复候选尚未正式应用，相关设计器功能不能提前认定全部通过，见[完整功能记录](full-functions-validation-20261004/README.md)。

浏览器只作填写预览，提交不发送计算结果。后端归一化输入后重新计算；审批修改和退回重提也重新计算，并记录真实派生变更。计算字段不能配置为节点可编辑，读取仍受节点字段权限限制，不向审批人额外返回隐藏的计算来源。本模块不处理余额扣减、工资核算或采购付款，业务规则应在独立业务服务内实现。

数字、金额、计算结果与明细数值列在网络中以精确十进制字符串回读，上下限也采用字符串；例如金额 `"999999999999999.99"` 不会变成浏览器舍入后的整数。页面数值控件使用字符串模式，预览和上下限比较使用精确运算，不先转为 JavaScript `number`。服务端执行与持久化继续使用 `BigDecimal`，包括提交历史、审批修改前后值、私人稿和父子流程映射；字段权限裁剪之后才编码。人员、部门、文件和实体编号仍为 JSON 整数，不全局修改数字契约。

兼容旧客户端提交的 JSON 数字：审批 `values` 的局部解码器从原始数值 token 读取十进制，不经过 `Double`。已有 JSON 快照保留原有小数位表示，新读取不会再次舍入；已经由旧客户端损失的精度不能凭空恢复。普通数字最多 18 位有效数字和 6 位小数，金额最多 2 位小数，绝对值不超过 `10^15`，同时检查自定义上下限。计算按模型配置的小数位舍入，表示上的“包含”依据实际持久表示判断，不替普通金额额外补小数零。

回读不一律展开科学计数：负 scale 的 `BigDecimal` 使用指数形式，例如旧输入 `1e3` 回读为 `"1E+3"`；其余值使用保留小数位的普通十进制形式，例如 `"500.00"`。上下限采用相同规则。数值比较仍按十进制值判断，因此 `1E+3` 与 `1000` 比较相等；`CONTAINS` 保持原有文本表示语义，不能在回读、未修改保存或退回重提时把 `1E+3` 变成 `1000`，从而让子串 `000` 意外命中。页面失去焦点后的格式展示不应改变未修改的提交值；此兼容修复不改写存量快照或旧条件算法。

## 申请与办理

发起人可以先保存草稿，必填项可暂缺，但已经填写的数据仍必须符合类型和约束。草稿只允许本人查询、编辑和删除，流程管理员也不能越权读取其他人的草稿。正式提交完整校验后才生成待办和通知。

开始填写时保存所选流程的完整版本快照。后台发布新版或页面自动刷新目录只提示新版可用，不更换正在填写的字段。提交旧版本发生冲突时保留输入；用户显式重新选择流程后才切换版本并清空旧字段，避免无提示地改变申请含义。

会签要求本批次有效审批全部通过；或签一人通过后使其余同批审批失效，额外加签仍必须完成；顺签按照配置人员顺序逐一激活，后续人员不会提前收到待办或获得参与者读取权限。指定用户顺序由配置保存，角色来源的人员按用户 ID 排序，避免数据库查询顺序变化。

抄送沿用流程推进自动投递。收件人在“抄送我的”查询和标记已读；读取不改变申请版本，也不算审批。抄送读取表单与历史仍受该抄送节点的字段权限控制。

审批动作必须同时满足接口权限、当前任务归属、当前节点动作配置和申请版本。并发点击或多个审批人同时办理，由事务行锁与版本检查保证只有一个当前决定生效，旧版本返回冲突而不是重复推进。查看页面时拥有权限，不代表稍后办理时仍有权限。

同一人在不同并行支路有多个待办时，详情提供本人待办选择，切换后重新读取该任务的动作、字段和退回路径；切换中不能提交上一任务的输入。确认办理时冻结任务编号和申请版本，服务端拒绝过期、他人或尚未激活的任务。

### 退回、驳回与重提

- **退回申请人**：填写理由，取消当前尚未完成的待办，申请进入“退回待修改”。发起人编辑原表单后重新提交，形成下一轮审批，从开始节点重新执行。
- **退回已办理节点**：只能选择本轮实际经过的前置审批节点，不能退到未经过的分支或任意未来节点。申请仍在审批中，目标节点创建新办理批次，随后重新执行下游节点；旧批次的通过结果不参与新批次计算。
- **驳回**：填写理由后结束该申请，不提供修改重提。需要补充材料时应选退回，而不是驳回。
- **撤回**：按流程开关允许发起人撤回在途申请，取消其待办；可继续修改并重提，产生新轮次。
- **管理员终止**：需管理权限和理由，将在途、退回或撤回申请正式终止。已通过或已结束的申请不能复活。

修改时不能改变申请人、所属流程、业务类型、原业务记录或原修订关联。重提冻结新的人员快照，并记录当轮提交表单；首次提交的表单仍保留，列表的提交时间表示最近一次正式提交。办理历史按轮次和节点批次保留，包含决定、时间、原因、字段变更及当轮表单，显示给用户时重新按字段权限遮蔽。

当前轮字段仅依据真实激活过的节点授权，排队人员即使早先已参与其他节点，也不能提前读取后续节点的字段或附件。历史字段及附件按其原轮次独立裁剪；曾实际激活的取消任务可保留合法旧历史读取资格，不因此读到重提后的新字段。排队任务交接的原人不继承接收人后来的激活权限；真实委托的原人仅按该委托任务取得查看资格，不能代办。

退回申请人或撤回后的“保存”仍是申请人的私人稿，标题、字段和新附件仅本人可见，管理权限也不能提前公开。其他原参与者继续看到上一正式提交轮及其合法审批修改；正式重提成功后才将私人稿变成新轮提交，失败保留原填写。旧版本已覆盖提交列的退回修改在读取时重建已提交视图，不改写原记录；无法证明旧标题时使用流程名称和申请编号。未提交 EDIT 的字段与附件不向其他人出现在历史中。

转交给新的合法审批人后，原人的该任务失效；加签创建本批次必须完成的附加任务。转交/加签检查目标人的当前启用状态、审批权限、数据范围和重复审批限制。评论、催办、超时提醒及工作台通知沿用同一通知与实时更新机制；标记通知已读不会消除待办。

手动催办覆盖申请中全部当前有效审批支路，按真实接收人去重；同一人承办多个并行节点只收到一次申请级提醒。排队、旧轮次、取消、抄送及委托来源人不计入。纯等待子流程或失败父实例没有有效待办时禁用，并显示原因；父实例仍有其他活动审批支路时只提醒这些支路。每项申请保持 30 分钟冷却，确认时固定打开版本，发生冲突需重新核对，不自动重试。

### 临时委托与人员交接（2026-10-04）

审批待办的“审批委托”管理本人创建和收到的安排。创建需要 `requests:delegate`、审批/查看权限，以及接收人的用户查看范围；本人身份由会话取得，不能替其他人设置。有效时段最长 90 天，可限定已发布启用流程或选择全部。账号行锁防止并发创建双重安排；重叠、自己委托自己、循环或转委托均拒绝。

安排只在节点任务实际激活时生效，顺签后续人员不会提前获得实例读取权。原人和接收人当前启用状态、授权、自审和重复审批规则重新检查；不适用时保留原审批人并显示原因，不跳过节点。委托不扩大节点字段权限。撤销或到期只停止后续应用，已经激活的任务仍归受托人；原人不能代为决定。需要变更在途任务时使用显式交接。

申请详情的“人员交接”供同时具有 `requests:manage/reassign` 与用户查看范围的管理员使用。原人允许已停用，新人须启用且有审批及申请查看权；只能调整在途、退回、撤回申请。当前任务保留办理历史并生成新任务，顺签等待任务保持原位置，到期时间不重新计算；未来节点人员也更新，但未激活时不成为参与者。每次交接携带打开时版本及理由，冲突保留输入，不自动覆盖重试。

实例保存交接覆盖记录，退回修改重提仍使用新审批人，并重新检查其权限。已发布流程和其他申请不变；新发起申请仍按流程配置解析。来源、接收人、委托记录和交接理由可在任务及历史追踪。当前提供逐申请交接，不自动替离职人员批量挑选接收人。

## 列表与运行查看

申请页面按“我发起的／草稿／待我审批／我已处理／我参与的／抄送我的”分类，并支持状态筛选。具有管理权限的全部申请列表也排除他人的草稿。详情提供申请表单、运行连接图、任务批次、办理记录及通知投递状态，表格使用共用序号与分页。

运行图只返回节点名称、类型、连接和办理状态，不把隐藏表单、未来审批人员配置或完整原始模型传给无权用户。顺签未激活人员不能仅凭知道申请 ID 读取详情。

## 二次开发接入

通用流程不依赖门户或具体业务表。其他业务实现 `WorkflowBusiness`，提供稳定业务类型，通过 Spring 注入注册；扩展应保持业务表、校验和副作用在其所属模块。

- `validateDraft`：草稿创建与每次保存修改前检查业务 ID、所属数据权限、修订关联、状态和业务版本。默认实现拒绝，新的业务适配器必须显式实现，不能因“只是保存草稿”跳过业务授权；未提交草稿的 `detail` 也必须按当前业务权限重新校验，不能借用正式审批参与者的读取资格。
- `submitted`：正式提交或重提时执行关联和状态变更，重新校验真实业务版本。内容审批接入只绑定指定修订，不直接发布未经审批的新正文。
- `completed`：通过、退回申请人、撤回和结束时处理业务状态。在退回/撤回已释放关联后再终止不会重复触发旧关联释放，避免覆盖后来新申请的关联。
- `detail`：返回用户可以看到的业务摘要。不要依靠摘要方法补救前面缺少的授权校验，不返回未经授权的隐藏字段。

适配器与流程决定同处事务；通知进入可靠投递记录，提交事务成功后再投递。历史与附件权限由通用引擎统一处理。API 数据结构、动作与状态参见 [接口说明](api.md)，权限边界参见 [权限说明](permissions.md)。

## 数据库与产品边界

当前数据库为 V31。V20 增加运行轮次与节点办理批次，V23 增加委托和任务来源，V24 增加退回重提保留的实例人员覆盖，V29 增加持久执行令牌与父子实例关联，V30 增加任务实际激活证据，V31 独立保存退回/撤回私人稿。旧任务只凭事务事件或确定已激活状态回填，无法证明激活的旧取消任务保守不授予字段权限。已有 `execution_state=null` 的单线申请继续按旧引擎及原快照办理。已安装系统由 Flyway 追加迁移，历史校验和保持不变。空库使用唯一公开交付 `database/mayday.sql`，不要向已有库重新导入。所有新表与字段有中文 COMMENT，不清空原申请和历史。

该实现支持有界 DAG 编排、可信计算、有限 AND/OR、限时委托与逐申请交接；不执行任意脚本。并行支持两至十条支路、专属汇合与嵌套，拒绝中途跨组连线、同字段并行写入及循环。子流程绑定不可变 GENERAL 版本，显式映射输入输出并检查类型、必填和父字段读写权，最多四层且禁止递归。子申请参与权限独立，不能独立编辑、重提或撤回；父申请退回、取消与终止按实际运行树传播。

失败节点持久保存并由审批管理员有理由恢复；不默默跳过失效人员或自动同意。每个模型最多四十节点、四十字段，每轮最多二百持久执行令牌、每次推进二百步，超限明确失败。模拟只基于初始填写，不预测审批人的人工编辑。完整 BPMN 导入导出、循环、定时自动决策、跨时区日历、电子签章及企业微信/钉钉外部消息不在当前范围。新增页面的真实浏览器验收见[完整功能记录](full-functions-validation-20261004/README.md)，最终状态以 E1–E6 证据为准。

模拟结果只对应本次模型、申请人和输入快照；任一项改变即清除旧结果并要求重跑。迟到响应不能覆盖新的输入，模拟失败保留填写内容，不展示上一轮成功路线。

计算规则引用字段或明细列时，设计器阻止直接删除、改变来源标识或在数字与金额之间切换类型，并明确指出引用它的计算字段；先显式调整计算规则，再修改来源。新增明细列不会复用仍被公式引用的旧标识。修改标题、顺序及无关属性不改变计算来源，历史申请仍按冻结版本办理。

待启动子流程因为固定审批/抄送人离职而失败时，详情先提供“子流程人员修复”：选择失败调用、原节点、新人员和理由，保存后再恢复。已生成的子申请在自己的详情进行人员交接。两种方式都保留固定发布版本和原申请人，不重新启用离职账号；新覆盖跨退回重提保存。已删除的原人员只能由 ALL 用户范围管理员替换，并记录原账号编号。原申请人自身失效时仍暂停，管理员可以终止申请，没有改写申请人身份的入口。
