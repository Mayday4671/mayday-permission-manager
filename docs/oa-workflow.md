# OA 流程使用与扩展

本轮从可配置审批升级为可完整办理的 OA 流程。保留现有模块、菜单、页签、业务弹窗、主题和不可变发布版本；不改写历史申请，也不通过更换模板绕过旧实例的字段权限。

## 验收范围

- 设计：表单控件、字段顺序/布局、字段说明、日期时间/日期区间/明细表；节点连接图、审批/抄送/条件/结束、人员来源、会签/或签/顺签、字段权限、版本与发布校验、预览模拟。
- 发起：本人草稿保存与继续编辑、提交校验、流程及人员快照、重复提交与旧版本保护。
- 办理：同意、终止性驳回、退回申请人修改、退回当前实际路径中已办理的审批节点；撤回、修改重提、转交、加签、评论、催办、管理员终止。
- 展示：待办/已办/我发起/我参与/抄送、状态过滤、运行轮次与节点办理批次、办理轨迹、当前节点和可退回目标、抄送已读。
- 安全：每次执行重新校验身份和权限；回退后取消旧待办，后续轮次不能使用旧审批结果；未来节点和其他申请的草稿不可读；附件和审计沿用字段权限。
- 场景：请假（日期区间）、报销（明细与金额）、采购（条件分支），覆盖多次退回/重提、顺签/会签/或签、撤回与并发决定、发布新版不改变在途申请。

## 原有问题与本轮修正（2026-10-02）

实屏已查看流程列表、设计器、节点编辑、表单设计和申请入口；本机没有已发布可发起的业务流程，因此运行行为使用新建的隔离验收数据检查，不向日常库塞入测试申请。

1. 驳回直接结束，没有退回与修改重提状态；没有持久申请草稿。
2. 节点按卡片排布，连接关系缺少直观图示；可读/可写字段用长多选控件。
3. 表单缺少日期区间、日期时间和业务明细；没有抄送、顺签。
4. 打开节点弹窗后未修改也出现丢弃提示，程序初始化与原始值快照存在时序问题。

上述问题已落实到模型、服务端执行、前端操作和数据库迁移中；原始截图保存在本机 `.local/oa-audit/`。最终验收记录与本指南分别维护，避免把功能实现等同于全部验收完成。

最新结果见 [OA 流程验收记录](oa-validation-20261002/README.md)：升级库与新建库各 135 项真实接口检查通过，设计器和手机组件已检查；完整浏览器办理链路仍待本次登录滑块授权。

## 设计与发布

1. 在审批分类中配置业务分类，在流程定义中从请假、报销、采购模板创建，或创建空流程。模板只生成可编辑草稿，不自动选择其他部门人员、不自动发布。
2. 表单设计的左侧添加控件，中间使用真实申请控件预览，右侧打开字段属性。字段 ID 是稳定引用，改显示名称不会破坏节点字段权限；顺序支持上移、下移，布局支持整行或半行。
3. 流程设计使用连接图；宽屏横向显示，条件分支单独占一条通道，窄屏从起点展开并允许移动/缩放。点击节点，在“节点设置／字段权限／办理设置”标签中编辑人员、出口、字段和动作，也可从节点后插入新节点。条件节点按条件顺序选择第一个命中的出口，其余走默认出口。另有节点列表供键盘操作；画布拖动位置只用于当前浏览，不是持久业务配置。
4. 每个审批节点配置人员来源（指定用户、角色成员、发起人部门负责人），选择会签、或签或顺签。字段矩阵逐项设置隐藏、只读、可编辑；可编辑必然包含可读。抄送节点仅支持隐藏、只读，不提供审批动作。
5. 保存草稿后先运行校验和模拟，再发布。服务端检查字段和类型、所有分支的节点引用、可达性、循环、人员、字段授权和动作，失败不会发布。模拟只计算预览，不创建真实待办。

发布版本不可修改。编辑和再发布生成下一版本；已经提交的申请继续使用提交时的版本、字段和节点，不能被后来的流程草稿修改。新版发起范围收回或流程停用后，旧申请仍可办理，退回后的重提会重新检查当前流程是否允许该申请人发起。

## 表单能力与限制

- 支持文字、多行文字、数字、金额、日期、日期时间、日期区间、单选、多选、人员、部门、附件、明细表，共 13 类控件；支持必填、输入提示、填写说明、文本长度、数值上下限。
- 明细表支持 1–6 列、最多 1–50 行（默认 20），列支持文字、多行文字、数字、金额、日期、日期时间、单选；属性弹窗在“明细列”逐列编辑，不把全部列的设置堆在一页。列的必填与数值/长度/选项约束由服务端逐行校验。明细不嵌套明细、附件或人员选择器。
- 日期区间要求开始不晚于结束；日期时间当前采用服务端业务本地时间，不是跨时区时间戳。金额以十进制比较，数值条件的 `0` 与 `0.00` 相等。
- 单流程最多 40 个字段、40 个节点。条件支持已有简单字段的比较和按顺序匹配，不把日期区间、明细等复杂对象转换为字符串比较。
- 附件沿用文件中心的账号、所属数据及字段授权；历史轮次使用过的附件保留引用，下载仍重新检查读取权限。

报销模板中的总金额目前需要填写，不自动汇总明细；请假天数也不自动扣除节假日。本模块不处理余额扣减、工资核算或采购付款，业务规则应在独立业务服务内实现。

## 申请与办理

发起人可以先保存草稿，必填项可暂缺，但已经填写的数据仍必须符合类型和约束。草稿只允许本人查询、编辑和删除，流程管理员也不能越权读取其他人的草稿。正式提交完整校验后才生成待办和通知。

会签要求本批次有效审批全部通过；或签一人通过后使其余同批审批失效，额外加签仍必须完成；顺签按照配置人员顺序逐一激活，后续人员不会提前收到待办或获得参与者读取权限。指定用户顺序由配置保存，角色来源的人员按用户 ID 排序，避免数据库查询顺序变化。

抄送沿用流程推进自动投递。收件人在“抄送我的”查询和标记已读；读取不改变申请版本，也不算审批。抄送读取表单与历史仍受该抄送节点的字段权限控制。

审批动作必须同时满足接口权限、当前任务归属、当前节点动作配置和申请版本。并发点击或多个审批人同时办理，由事务行锁与版本检查保证只有一个当前决定生效，旧版本返回冲突而不是重复推进。查看页面时拥有权限，不代表稍后办理时仍有权限。

### 退回、驳回与重提

- **退回申请人**：填写理由，取消当前尚未完成的待办，申请进入“退回待修改”。发起人编辑原表单后重新提交，形成下一轮审批，从开始节点重新执行。
- **退回已办理节点**：只能选择本轮实际经过的前置审批节点，不能退到未经过的分支或任意未来节点。申请仍在审批中，目标节点创建新办理批次，随后重新执行下游节点；旧批次的通过结果不参与新批次计算。
- **驳回**：填写理由后结束该申请，不提供修改重提。需要补充材料时应选退回，而不是驳回。
- **撤回**：按流程开关允许发起人撤回在途申请，取消其待办；可继续修改并重提，产生新轮次。
- **管理员终止**：需管理权限和理由，将在途、退回或撤回申请正式终止。已通过或已结束的申请不能复活。

修改时不能改变申请人、所属流程、业务类型、原业务记录或原修订关联。重提冻结新的人员快照，并记录当轮提交表单；首次提交的表单仍保留，列表的提交时间表示最近一次正式提交。办理历史按轮次和节点批次保留，包含决定、时间、原因、字段变更及当轮表单，显示给用户时重新按字段权限遮蔽。

转交给新的合法审批人后，原人的该任务失效；加签创建本批次必须完成的附加任务。转交/加签检查目标人的当前启用状态、审批权限、数据范围和重复审批限制。评论、催办、超时提醒及工作台通知沿用同一通知与实时更新机制；标记通知已读不会消除待办。

## 列表与运行查看

申请页面按“我发起的／草稿／待我审批／我已处理／我参与的／抄送我的”分类，并支持状态筛选。具有管理权限的全部申请列表也排除他人的草稿。详情提供申请表单、运行连接图、任务批次、办理记录及通知投递状态，表格使用共用序号与分页。

运行图只返回节点名称、类型、连接和办理状态，不把隐藏表单、未来审批人员配置或完整原始模型传给无权用户。顺签未激活人员不能仅凭知道申请 ID 读取详情。

## 二次开发接入

通用流程不依赖门户或具体业务表。其他业务实现 `WorkflowBusiness`，提供稳定业务类型，通过 Spring 注入注册；扩展应保持业务表、校验和副作用在其所属模块。

- `validateDraft`：草稿创建与每次保存修改前检查业务 ID、所属数据权限、修订关联、状态和业务版本。默认实现拒绝，新的业务适配器必须显式实现，不能因“只是保存草稿”跳过业务授权；未提交草稿的 `detail` 也必须按当前业务权限重新校验，不能借用正式审批参与者的读取资格。
- `submitted`：正式提交或重提时执行关联和状态变更，重新校验真实业务版本。内容审批接入只绑定指定修订，不直接发布未经审批的新正文。
- `completed`：通过、退回申请人、撤回和结束时处理业务状态。在退回/撤回已释放关联后再终止不会重复触发旧关联释放，避免覆盖后来新申请的关联。
- `detail`：返回用户可以看到的业务摘要。不要依靠摘要方法补救前面缺少的授权校验，不返回未经授权的隐藏字段。

适配器与流程决定同处事务；通知进入可靠投递记录，提交事务成功后再投递。历史与附件权限由通用引擎统一处理。API 数据结构、动作与状态参见 [接口说明](api.md)，权限边界参见 [权限说明](permissions.md)。

## 数据库与产品边界

本轮数据库为 V20；已安装系统由 Flyway 追加 `V20__oa_workflow_lifecycle.sql`，历史 V1–V19 不改写。空库使用唯一公开交付 `database/mayday.sql`，不要向已有库重新导入初始化脚本。新增轮次、办理批次、已读及表单快照字段均有中文 COMMENT，旧记录回填到第一轮，不清空原申请和历史。

该实现覆盖常见内部请假、报销、采购、内容审批的核心链路，并不宣称兼容完整 BPMN。当前不提供并行汇合网关、子流程、定时自动决策、复杂条件表达式、跨时区日历、表单公式、审批代理/离职自动交接、电子签章以及企业微信/钉钉外部消息通道。人员失效或权限撤销时停止推进并明确报错；允许撤回或管理员终止，不默默跳过审批，也没有自动管理员重指派工具。大规模多实例部署应按照通知、文件存储与数据库并发边界单独验收。
