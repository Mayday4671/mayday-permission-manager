# Art Design Pro 核心功能实查记录

检查日期：2026-09-17。对象：[Art Design Pro 前端演示站](https://www.frontend.artd.pro/)。通过已登录的内置浏览器逐页打开并检查，共覆盖 21 个主页面，另检查关键表单、权限配置、流程设计器和详情。截图保存在本目录的 `screenshots` 中，对应 DOM 记录为同名或相邻编号的 `.txt` 文件。

## 本轮范围与约定

- 优先补齐系统管理、通知中心、审批中心、内容管理，并接入真实 Java 后端。
- 保持 Mayday 现有单侧菜单及页面标签页；不采用参考站左侧模块栏加二级菜单的导航结构。
- 新增、编辑、审批处理和详情统一采用弹窗；参考站部分抽屉不照搬。
- 页面保持紧凑，去掉装饰性介绍、口号、权限提示横幅和无业务作用的统计卡片。
- 内容管理负责前台实际展示；网站配置负责公共品牌、SEO、联系信息等配置。
- CRM、电商、人事、招聘等行业示例暂不纳入。任务调度、系统监控不属于这次四个模块的实查覆盖。
- 本轮是页面和交互研究，未修改应用功能代码。以下“落地要求”是后续实现约束，不表示功能已经完成。

## 对 Mayday 的落地要求

### 权限与基础组件

- 菜单可见、按钮可用、接口授权、数据范围和字段权限分别校验。不能只在 React 中隐藏按钮。
- 数据范围覆盖本人、本部门、部门及下级、自定义部门、全部；详情、列表、导出、统计遵循同一范围。最终规则与现有权限模型整合，防止多角色叠加产生意外放权。
- 角色授予、部门调整、菜单权限、敏感字段查看、导出和审批动作单独授权并记录审计。
- 统一复用查询栏、表格工具、分页、列设置、状态显示、人员/部门选择器、表单弹窗、详情弹窗、富文本及上传组件。避免各页面自行实现同一套交互。
- 菜单分组保持当前方式，页面标签页继续支持切换、关闭和刷新；宽表使用合理固定列及局部滚动，不让整页横向溢出。

### 通知与审批

- 区分发布者的通知管理与接收者的收件箱；按接收者存储阅读状态，明确撤回和过期的处理方式。
- 发送时校验发布权限及接收范围，保留接收对象快照。通知可关联审批任务或内容记录，由后端再次检查目标访问权限。
- 流程定义与运行实例分离；申请固定使用提交时的定义版本、表单快照和业务版本，修改模板不改变正在进行的申请。
- 节点字段权限和操作权限由后端执行；审批动作防重复提交，并处理多人审批及并发状态变化。
- 内容发布审批直接绑定文章 ID 和内容版本。审批后若文章发生实质修改，需要重新审核，不能用旧审批发布新内容。

### 后台内容驱动前台

- 内容正文、封面、摘要、分类、标签、排序、推荐和置顶由后台维护，前台通过公开接口读取。
- 公开接口只返回公开范围、已发布、在有效发布时间内且未删除的内容。草稿、内部内容、待审、已下架、回收站内容不能通过列表、详情、搜索或附件地址泄露。
- 发布需要审批时，由审批结果与内容版本共同决定是否允许发布；不需要审批的业务也必须检查发布权限。
- 支持定时上线、定时下线。下架和删除及时影响公开列表、详情及缓存。
- 恢复回收站内容时建议回到草稿，防止恢复动作意外重新公开；这是我们的设计要求，未验证参考站采用此行为。
- 网站名称、简介、SEO、联系信息、版权及备案等通过明确的公共配置白名单提供给前台；后台安全参数不进入公共接口。
- 可在以上基础上增加首页栏目、轮播和推荐位配置；这是前后台联动的扩展设计，并非此次已在参考站核实的功能。

## 设计与可用性观察

- 值得采用：通知收件箱的列表/正文布局；字典及字典项联动；审批定义与运行记录分开；内容的发布状态、预览与回收站。
- 不照搬：双层侧栏、装饰性大标题与介绍卡片、参考站的抽屉表单、共享账号画像示例、手工修改互动计数。
- 当前约 1010px 宽的系统页面截图中，双层侧栏占用空间较多，字典和菜单表格挤压明显。我们保留单侧菜单，并验证窄屏下的表格和弹窗布局。
- 操作日志行操作使用图标容器，检查到的 DOM 未提供明确按钮名称；可访问名称和键盘操作存在风险。我们应使用有名称的按钮与提示。未做完整读屏、键盘、对比度或缩放测试，不声明符合无障碍标准。
