# 作为新项目底座使用

这套系统适合单组织、共享数据库的企业内部后台，以及带公开内容门户的中小型业务系统。账号、角色、部门、岗位、操作权限、数据范围、用户敏感字段、菜单、日志、通知、内容和审批可直接复用。新业务需要接入资源权限与服务端数据范围，不能仅新增菜单就认为授权已经完成。

2026-10-02 已重新构建并启动本机服务，独立恢复安装及全新空库各 104 项接口检查通过，重启与数据保留核对通过。见 [本次启动与复用检查](startup-reuse-validation-20261002/README.md)，其中明确区分普通后台回归、UDP 环境要求及未执行的后台视觉验收。

目前不是多租户 SaaS 或独立身份平台：没有租户隔离、SSO/OIDC/SAML、MFA、任意 ABAC 策略、通用可配置字段权限平台。用户邮箱/电话和审批字段已做细粒度控制，其他新业务字段需单独定义。数据范围按多个角色取并集，没有显式拒绝规则。共享基础资料（如部门树、岗位、分类）与角色目录采用模块权限，不声称全部都是部门级隔离。

## 新建项目的最短路径

1. 复制源码目录中的 `backend`、`frontend`、`scripts`、`tests`、`database`、`docs`、Compose 文件、README、`.env.example` 和 `.gitignore`。保留 Maven Wrapper（包括 `backend/.mvn`）及前端 lockfile。
2. **不要复制**日常 `.env`、`.local`、真实数据库备份/卷、构建输出、`node_modules`、缓存和日志。当前源码已提交到 [GitHub 仓库](https://github.com/Mayday4671/mayday-permission-manager)，可克隆后为新业务另建仓库或分支；数据库备份与代码版本管理分别保留。
3. 将 `.env.example` 复制为新项目 `.env`；替换管理员和数据库口令，保持 `SEED_DEMO_DATA=false`。Compose 顶部项目名、数据库名、端口按新项目调整，使用独立目录和独立数据卷，不能指向旧业务库。
4. 执行 `docker compose up -d --build`，Flyway 会从空库迁移到 V17。需要手动建库时，先把 `database/mayday.sql` 一次导入独立空库，再启动应用；文件已包含 V17 基线，无需关闭迁移或放宽校验。两种安装方式均由应用创建管理员和必要基础资料，没有演示成员、部门或文章。UDP 转发默认停止；仅需独立转发时可直接复制 `backend/mayday-netty`，不需要整个后台。
5. 登录后配置站点名称、联系信息、前台主题和实际组织；创建普通角色，按最小权限授权。账号、角色、组织、业务配置在数据库内，重启不重置。
6. 在增加业务前运行前端构建与隔离基线验证，保留结果。默认端口均绑定本机；正式部署另行配置域名、HTTPS 和反向代理。

`SEED_DEMO_DATA=true` 只影响首次初始化。已有 admin 时不追加演示记录，也不会删除业务数据；更改 `ADMIN_PASSWORD` 不会重置已有密码。需要体验演示请另建独立空库，不要清空业务数据卷。

UDP 是可选业务能力，普通后台安装不要求预先提高内核 socket 缓冲。构建时，缓冲不足的环境会明确跳过三项 UDP 收发集成测试，但实际缓冲启动保护仍执行。API 基线在此环境验证拒绝启动、权限与版本边界，并输出未验证成功启停的说明；UDP 部署验收应设置 `API_TEST_REQUIRE_UDP_BUFFERS=true`，同时满足 `docs/udp-relay.md` 的系统参数与打流条件。不能把普通后台基线通过视为 UDP 高吞吐验收通过。

## 接入新的业务资源

以“工单”为例，先明确数据所有者和所属部门，决定工单转派时权限如何变化；跨组织或客户隔离不能直接拿部门字段冒充租户字段。

1. 新增实体、Repository、请求/响应 DTO、服务；使用独立业务表，不把复杂业务塞进 `sys_entry.value`。当前已到 V17，新增迁移从下一个未占用版本（现为 V18）开始，写完整表/列 COMMENT，再同步 `database/mayday.sql` 中的当前结构、基础资料和基线版本。
2. 在 `PermissionCatalog.GROUPS` 注册 `tickets` 及 view/create/update/delete/export 等实际支持动作；需要行级范围则设置 `scoped=true`。角色编辑页面、后端范围白名单及会话摘要现在统一从该目录派生。
3. **操作授权**：Controller 使用 `@PreAuthorize("@access.has('tickets:view')")` 或 Service 入口 `access.require(...)`；认证通过不等于拥有模块权限。
4. **列表范围**：`access.filter("tickets", "ownerId")` 与业务条件组合；当前通用策略约定实体的部门属性名为 `departmentId`。分页、总数、导出、搜索选项和图表都复用同一过滤，不先全量查再在前端过滤。
5. **单条及写入**：读取目标后调用 `access.checkData("tickets", ownerId, departmentId)`。创建记录时服务端赋予 ownerId/departmentId，转派需额外权限与目标校验；批量逐条检查、事务整体回滚，不能信任前端传入的身份字段。
6. **字段与关联**：DTO 白名单读写；敏感字段单独授权；文件下载、详情直链、关联选择器和异步任务都校验业务访问资格。乐观锁用于编辑覆盖保护，不能代替权限。
7. 前端复用 `ResourcePage`、`FormModal`、异步选择器与 QueryState；在 `App.tsx`、`workspace-model.ts`、`NavigationCatalog` 登记页面，并用新增迁移写入导航。菜单权限必须与页面匹配，操作仍走后台接口鉴权。
8. 加真实接口回归：无登录、无权限、同部门、范围外已知 ID、敏感字段、导出/统计、撤权后旧会话、过期版本及批量混合失败；有发布/审批再验证业务版本绑定。

通用范围算法可用于符合上述所有者/部门约定的资源；业务语义不同就建立自己的策略服务，并明确授权契约，不把 SELF 或 CUSTOM 强行套用到所有场景。

## 二次开发优先补齐的能力

当前适合以单组织后台为底座继续开发：可以复用登录、权限、组织、公共页面、通知和审批；每个新增业务仍需明确自己的操作、数据范围、字段与关联访问规则，并完成接口回归。纯净初始化、模块分层和已有文档减少接入工作，但不等于任意业务无需适配即可上线。

建议按以下顺序扩展，以下均是建议范围，尚未实现：

1. **业务模块模板与生成工具**：提供一套可运行的工单示例，覆盖实体、DTO、服务、分页、权限、版本、迁移、React 表格/表单和越权测试。生成器以这套模板为基础，保留业务逻辑扩展位置，优先避免漏接权限和数据范围。
2. **可选模块开关**：按新项目需要关闭门户、审批、采集或 UDP，同时一致处理后端定时任务、接口、前端路由、菜单和权限目录。当前源码模块化，但应用仍统一组合所有模块；仅隐藏菜单不等于停用模块。
3. **工程与接口契约**：增加自动构建、单元/权限/空库/升级回归的持续集成，发布可追溯版本；补充机器可读接口描述及 TypeScript 请求类型生成。统一检查客户端错误状态，例如当前不存在的公开 API 会被通用异常兜底返回 500，应进一步明确为 404。
4. **文件与批量业务**：将存储抽成适配契约，支持本地或对象存储；增加可复用的导入预览、逐行校验、错误清单、后台导出与进度。当前 MySQL 文件正文及 10 MB 上传适合小附件，不适合大规模采集素材或业务文件。
5. **消息和审批的业务接入**：延续可靠站内事件机制，增加统一消息模板、业务链接、投递状态与外部渠道适配；补业务审批示例和完成回调契约。复杂流程才追加催办、超时和代办策略，不能由“读消息”自动代替业务完成。

多实例、单点登录、MFA、多租户按明确业务需求另行增加。多实例尤其需要先处理验证码一次性消费、共享限流/缓存与调度并发；租户隔离必须覆盖查询、写入、文件、通知、审批和后台任务，不能只加一个租户字段。

## 当前上线条件与限制

- **网络与凭据**：示例口令只适合本地体验。生产使用独立随机口令、HTTPS、可信代理配置和受限数据库网络；不把真实秘密写入参数表、前台代码或仓库。
- **页面嵌入**：Nginx 默认使用 CSP frame-ancestors 和 X-Frame-Options 禁止其他站点嵌入页面，避免点击劫持。需要合法嵌入时应限定明确来源并重新评估后台操作流程，不能直接删除所有保护头。
- **数据库权限**：当前 Compose 应用账号负责 Flyway DDL 与运行 DML，适合本地部署。正式环境建议分开迁移账号与运行账号；由迁移任务执行 DDL，再以 DML 最小权限运行并关闭应用自动迁移。不要直接删去 Flyway 历史。
- **高可用**：登录限流和参数缓存在进程内。多实例需要共享限流、缓存失效机制及经过验证的调度/事件运行策略；不能仅复制多个容器就宣称多节点能力验收完成。
- **审计**：数据库操作日志支持查询、导出及受控清理，但没有防篡改存储或外部审计中心，也没有覆盖任意业务字段的完整变更差异；审批字段另有变更历史。
- **文件**：当前文件正文在 MySQL，10 MB 上传限制；提供业务下载鉴权、类型白名单和附件响应，但未集成恶意文件扫描或对象存储。大文件/高吞吐场景需要适配。
- **身份安全**：会话随机令牌、密码摘要、撤权与登录限流已实现；高风险系统需再配置 MFA、统一身份、敏感操作二次认证等具体要求，不能把普通后台功能等同于完整安全认证。
- **工程交付**：提供本机构建、真实 MySQL 空库/升级回归和备份恢复脚本。尚未给出项目 CI 平台流水线、生产容量指标、跨地域容灾证明或完整依赖供应链认证。

本次检查参考 [OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)的默认拒绝、每次请求校验与最小权限原则。[OWASP ASVS](https://owasp.org/projects/asvs)提供更完整的验证基线；本项目没有做完整 ASVS 逐条验证，不标注 ASVS 等级或“无漏洞”认证。
