## 真实归档工具与异常边界

- 实际调用本机 7-Zip 处理生成的小型 7z：Unicode 文件名、嵌套目录、服务分页、图片单项读取、Range、416、损坏归档、提取上限与临时文件清理均通过。
- RAR 使用 libarchive 官方固定测试样例，校验 336 字节和 SHA-256，实际读取两个纯文本条目，过滤 Unix 符号链接。来源和固定版本见 `TelegramSevenZipIntegrationTest`。
- ZIP 由 Java 标准库处理；服务测试覆盖路径穿越、分页、图片内容、Range 与临时文件清理。前端归档组件测试覆盖读取失败后的重试、截断文件拒收，避免弹窗无限显示“正在读取”。
- 归档工具测试不伪称来自极搜的压缩包端到端测试；未执行归档内文件。加密、分卷、递归提取和超过配额的文件仍明确拒绝。

## 部署及功能边界

本机 Windows 已配置 FFmpeg、FFprobe 和 7-Zip 的受控路径。其他部署环境仍需安装对应工具并配置路径；不能仅复制本机路径。此轮不包含重新执行全系统、全数据库基线或真实 iOS 设备兼容性认证。

Telegram 资源被删除、限制保存、账号无访问权、机器人未返回相应类型按钮或服务端配额不足时，系统显示相应失败原因，不用“没有媒体”掩盖失败。不能保证外部搜索返回的所有链接永久有效。频道追赶仍是有界定期拉取，不承诺推送或绝对无遗漏；其权限、游标和并发边界由专项测试覆盖，不使用真实账号任意加入频道或等待未知频道发布来伪造验收结论。
