# 图片采集

入口：后台 **内容管理 → 采集数据 / 采集配置**，两个独立菜单、路由和标签页。数据页只负责搜索与浏览文章、图片；配置页只负责规则、执行控制与执行记录。从公开网页或公开 JSON 接口采集文章与图片，正文保存为纯文本，图片保存到文件中心。列表和每篇详情拥有独立的分页规则，可以处理“列表翻页 → 进入详情 → 详情里的图片继续翻页”。

## 使用步骤

1. 在“采集配置”新增配置，填写配置名称和完整入口地址。直接采当前网页的图片时关闭“先进入详情页采集”；采列表下的文章或图集时打开它并填写详情链接选择器。
2. 配置“列表分页”。如果入口就是一个图集，直接在这里配置该图集的分页即可。
3. 进入详情模式下，单独配置“详情分页”。每篇详情从自己的首页开始计数，不会沿用列表的页码。
4. 在“图片与限额”配置图片选择器、地址属性、额外图片域名和限额。“测试入口页规则”仅请求并解析入口页，显示最多 10 个图片、详情、分页地址；不会保存图片或自动执行后续链接。
5. 在“文章内容”开启“同时采集文章”，按需要设置标题、正文、作者和发表时间的 CSS 选择器或 JSON 路径。HTML 留空自动识别常见文章结构，JSON 留空读取 `/title`、`/content`、`/author`、`/publishedAt`。自定义路径未匹配时不会猜测其他内容。
6. 保存后在配置页点击“开始采集”。在“采集数据”浏览当前账号有权查看的文章，可搜索标题、翻页。数据页优先显示三行，根据可用高度同步调整卡片与封面，每页最多 24 篇；矮窗口减为两行或一行，紧凑卡片不显示摘要，保留标题、数量、来源和日期。窗口缩放会保留原来浏览位置所在页。点击卡片打开右侧抽屉，图片按可用空间分页，底部保留分页控件；点击缩略图放大，支持上一张、下一张、缩放和旋转，关闭预览后回到原缩略图页码。长正文通过“文章正文”标签单独查看。
7. “采集配置”保留停止/继续/重试等操作；“执行记录”只显示图片、列表页、详情页的请求状态与失败原因，不再嵌套数据卡片和图片浏览。记录按弹窗可用高度分页，每页最多 10 条，较矮窗口自动减少；地址和来源页各显示一行，悬停查看完整值。窗口缩放保留原浏览位置所在页，筛选后回到第一页。配置创建与编辑仍使用居中弹窗。

## 文章与配图

每篇详情首页对应一张卡片。详情分页的正文按遍历顺序归并，重试会更新原页面而不会重复拼接；不同文章引用相同图片时保留各自关联，存储仍按地址和内容去重。直接采当前网页时，入口及其分页归为同一篇文章；列表进入详情模式只把详情保存为文章。

卡片包括封面、标题、可用摘要、来源域名、采集日期和实际图片数量；抽屉展示作者、发表时间、详情页数与等待/失败数量。只渲染当前页缩略图，并按视区加载图片；缩略图序号跨页连续，放大预览序列包含整篇文章所有已保存图片，不局限于当前缩略图页。图片分页每页最多 24 张，按抽屉宽高取完整行，手机自动减少列数和行数。只有窗口高度不足以放下一行缩略图，或用户主动切换到长正文时，才使用内部滚动；不隐藏全局滚动条来遮盖内容溢出。正文不保存远端可执行 HTML，去除脚本、导航、表单等结构，保留段落换行；图片通过本系统鉴权接口按需加载，不直连来源站点。没有正文时展示原始标题和配图，不生成或补写正文。外站脚本动态生成的文字需要另行配置公开 JSON 接口。

原站标题中的“10P”等字样保留原文，不作为采集成功数量；成功数量按已入库且去重后的文件统计。图片选择器若只匹配一张、任务限额不足、下载失败或详情分页没有配置，都可能造成数量不足。任务图片上限作用于整个任务，并非每篇文章的限额；达到上限时抽屉提示可能不完整。需要采完整图集时，应匹配正文中的全部图片并配置足够的图片及详情页上限。

单页正文最多 20,000 字符，详情一次展示最多 100,000 字符，达到上限会提示截断并提供原文地址。文章列表按任务归属检查权限，图片查看和下载继续要求 `crawler:download`。旧任务在 V13 只保存过标题和图片，升级不会假造正文；复制任务、启用文章采集并运行后才生成文章卡片。采集文章只保存在后台采集结果，不会自动发布到前台门户。

配置支持停止、继续、失败项重试和复制。规则一旦执行便锁定；需要调整时复制配置，避免续跑时混用不同的分页规则。删除有文章的配置只归档来源记录，不删除已有文章、正文与图片引用；配置从列表消失且不能再编辑、启动、停止或重试，数据页仍按原所有者权限读取图文。尚未产生文章的空配置可以物理清理，文件继续保留在文件中心。数据仍引用图片时，文件中心禁止直接删除该图片。

## 分页规则

- **只采集当前页**：不跟随分页链接。
- **下一页链接**：HTML 选择器匹配一个带 `href` 的下一页链接；JSON 使用指向下一页 URL 的 JSON Pointer。没有下一页即停止。
- **页码链接集合**：一次发现多个页码链接，并在已发现页面继续提取。相同地址只入队一次，循环链接不会无限访问。
- **页码 / 偏移量模板**：按“起始值 + 当前页序号 × 递增值”生成后续地址。例如入口为 `https://example.com/list?offset=0`，模板为 `https://example.com/list?offset={page}`，起始值 `0`、递增值 `20`，后续请求偏移量 `20`、`40`。
- **游标接口**：JSON 的下一游标路径返回标量游标，模板包含 `{cursor}`。自动进行 URL 编码；游标为空、缺失或重复地址时停止。

模板支持：`{url}` 为当前分页组的首页；`{base}` 为组首页去掉查询参数和文件扩展名；`{origin}` 为入口协议与域名；`{page}` 为递增的页码或偏移量；`{cursor}` 为已编码游标。

例如图集首页 `https://example.com/gallery/42.html`、续页 `42_2.html`、`42_3.html`，详情选择模板 `{base}_{page}.html`，起始值 `1`、递增值 `1`。第一页始终使用发现的详情原地址，每篇图集的模板独立展开。模板无法自动判断网站是否还有下一页，因此必须设置准确的页数上限；不存在的页面会按失败记录展示。

## HTML 示例

```html
<!-- 列表：详情链接与下一页链接 -->
<a class="article-title" href="/gallery/42.html">图集</a>
<a class="next" href="?page=2">下一页</a>
<!-- 详情：图片可能延迟加载，并有独立的下一页 -->
<article class="gallery"><img data-src="https://img.example.com/a.jpg"></article>
<a class="next" href="/gallery/42_2.html">下一张</a>
```

详情链接选择器填 `a.article-title`，列表和详情分页选择器分别填 `a.next`，图片选择器填 `.gallery img`。图片来自其他域名时，在额外图片域名添加准确的 `img.example.com`。

图片属性按填写顺序尝试，例如 `data-original`、`data-src`、`data-srcset`、`srcset`、`src`。`srcset` 取描述符最大的候选，忽略 `data:` 内嵌图。也可以选择指向原图的 `<a>`，并将图片属性改为 `href`。HTML 的相对地址以最终响应地址解析，支持 BOM/meta 标记的旧站编码。

## JSON 示例

```json
{
  "data": {
    "images": [{ "url": "https://img.example.com/a.png" }],
    "nextCursor": "abc&123"
  }
}
```

响应格式选 JSON；图片数组路径填 `/data/images`，对象中的 URL 路径填 `/url`；分页选游标接口，下一游标路径填 `/data/nextCursor`，模板如 `https://example.com/api/images?cursor={cursor}`。若数组直接存地址字符串，对象 URL 路径留空。JSON 列表进入详情模式时，配置详情链接数组路径，其条目同样可以是字符串或包含 URL 的对象。

## 权限与运行边界

权限分为 `crawler:view/create/update/delete/run/stop/download/all`。运行额外要求 `files:create`；预览解析要求 `crawler:view` 和 `crawler:run`。默认只访问自己创建的任务，“管理所有任务”是独立权限。非管理员不会因升级而自动获得采集权限。管理员替他人启动任务时，文件仍归任务创建者。

账号/角色停用或撤回执行权限后，下一次领取和当前结果保存都会重新检查；正在进行的外站请求可能结束，但结果不会入库，任务转为已停止。任务队列保存在 MySQL，重启后可恢复；过期租约或停止前的工作器不能覆盖新执行结果。外站请求不持有数据库事务，也不占用审批通知和内容发布的调度线程。

仅支持公开的 HTTP/HTTPS GET、默认 80/443 端口；分页和详情须在入口域名，图片可额外配置最多 10 个准确域名。每次连接和每次重定向都校验公网 IP，拒绝回环、内网、链路本地、保留地址及含内网结果的 DNS；不接受自定义认证头、Cookie、代理或脚本。不会登录目标网站、处理验证码、绕过访问限制，也不会运行页面 JavaScript。纯 JavaScript“加载更多”页面需要配置其公开数据接口；不提供浏览器点击、POST 接口、登录态采集或自动识别所有网站的承诺。任务由操作人手动创建并启动，没有定时巡检功能。

每组列表或详情最多 100 页、每任务最多 200 篇详情和 500 个图片地址；图片地址达到上限后不再添加。单张图片最多 8 MB、单任务保存上限 200 MB、最多 5000 条队列记录；PNG/JPEG/GIF/WebP 根据签名识别，拒绝 HTML/SVG。每账号最多 30 个未结束任务、3 个运行任务。请求间隔 500–10000 ms，每项失败最多自动尝试 3 次，再由用户选择重试。队列是单工作线程，多个任务轮流领取，不追求高并发抓取。同任务按规范化地址及图片 SHA-256 分别去重；不跨账号共享图片摘要。

## 开发与验收

- 后端独立模块 `backend/mayday-crawler`；队列服务、HTTP 安全边界、纯页面解析器、控制器分离。
- 前端规则表单复用于列表和详情；使用公共表格、序号、查询偏好和操作弹窗。
- 对外数据库只交付 `database/mayday.sql`（V15，39 张业务表、359 个字段）；已有库由内部迁移保留旧任务、文章与文件，V15 新增配置归档标记并拆分菜单。
- `node scripts/verify-crawler.mjs`：新建随机命名的临时 MySQL，导入单一 SQL，用确定性网页夹具验证完整队列及事务，结束后清理；需要 Docker 和 Java 21。外站 HTTP 在此套测试中替换为固定响应，不代表特定网站已验收。
- `node scripts/verify-baseline.mjs`：在现有库副本及空库运行迁移、完整接口权限回归、重启和清理核对，包含 `tests/crawler.test.mjs`。

选择器语法参考 [jsoup 官方说明](https://jsoup.org/apidocs/org/jsoup/select/Selector)。生产采集器通过 [Apache HttpClient DNS Resolver](https://hc.apache.org/httpcomponents-client-5.6.x/current/httpclient5/apidocs/org/apache/hc/client5/http/DnsResolver.html) 将审核后的地址用于建连。
