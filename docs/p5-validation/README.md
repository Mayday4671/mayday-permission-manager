# P5 审批运行与设计器验收

## 已完成能力

- 四个业务入口：审批分类、流程定义、审批申请、审批待办；设计器独立页签，所有节点、字段、申请、详情与处理均用弹窗。
- 流程草稿与不可变发布版本、申请模型/人员/原始表单快照、版本冲突和实例行锁；旧实例保持旧版本。
- 指定人员、角色、部门负责人；顺序/条件节点、会签/或签、转交/必签加签、发起范围、自审/重复人员/撤回规则。
- 文字、数字/金额、日期、单选/多选、人员、部门、附件；字段可读/可写限制同时作用于服务端详情、操作与历史。
- 送审绑定准确文章修订；通过只批准该修订，发布仍独立授权。新稿不能继承旧审核，送审详情保留历史正文。
- 可靠站内通知：业务事件同事务提交，异步投递、行锁/唯一键防重、失败退避和管理员重试。
- 图形视图、键盘节点列表、字段排序、预览模拟，以及侧栏/页签/后退/刷新时的未保存保护。

## 浏览器实际操作

在独立数据库副本和 15174 前端验证：管理员通过界面建立“内容发布审核”，配置指定审核人、会签、可读字段和节点动作；模拟正常路径，保存并发布版本 1。专用内容编辑账号提交文章修订 1，页面变为待审核；管理员收件箱收到通知，关联入口打开审批详情，在处理弹窗中同意，历史追加决定；有发布权限的管理员单独发布，门户文章正文与获批快照一致。

核对了返回设计器、图形/表单设置、字段弹窗，以及未保存时菜单切换、刷新和关闭页签的取消/放弃分支；取消保持修改，放弃后重新打开读取已保存模型。780×900 节点长表单中标题/按钮可见，正文正常滚动。验收发现并修复了子审批弹窗被详情遮挡的问题。

## 关键集成回归

`tests/workflow.test.mjs` 的 10 个子场景覆盖：发布模型拒绝循环/不可达/绕过审批、会签并发、或签加签转交、旧版本实例、权限撤回、角色/负责人/条件解析、字段修改追溯和附件隔离、下一节点权限失效事务回滚、真实通知投递失败恢复防重，以及文章新旧修订/驳回/撤回/重提/通过/发布完整闭环。

通知失败通过隔离库的专用测试事件制造存储失败，确认通知半成品回滚、重试成功且事件只产生一条通知；生产接口没有故障注入或测试清理后门。原始表单单独保存，修改历史按读者的字段范围过滤。

最终双数据库、清理、重启及本机升级证据统一列入 [P6 交付验收](../p6-validation/README.md)。

## 明确范围

支持无循环的顺序与简单条件流程，不包含并行网关、子流程、撤销已完成审批、自由表达式脚本或完整 BPMN。模型只展示引擎能够执行的节点。模拟不会创建申请或通知；用户/角色后续变动不替换已创建实例人员，但处理和激活下一节点仍检查实时账号权限。
